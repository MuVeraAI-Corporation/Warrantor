          Nothing has been granted on this machine yet

          A warrant is written, signed permission for an AI agent to do one stated job: what it is for, which tools it may use, which paths it may write to, and when the permission runs out. Granted inside a git repository, it also prepares a separate worktree on a branch of its own, so the agent's file edits stay off your working copy until a person settles the warrant.

          Those bounds are not all held the same way, and a warrant says which is which rather than implying one guarantee. The deadline and the delegation limit are enforced: an operating-system process link, and a signature the agent cannot forge. The tool allowlist, the egress hosts and the staged effect classes are mediated — refused by the broker the agent's tool calls pass through, which is real against an agent using its tools and is not a cage: what does not go through the broker is not decided by it. Written paths and spend are observed: measured and reported, never refused as they happen. Warrantor makes what an agent did legible, reviewable and hard to misreport. It composes with a sandbox; it is not one.

          Staging is narrower than the word suggests, so read it as a list and not as a promise. An effect waits for review only when the warrant names its class and this build knows how to stage that particular tool — today, the GitHub effects, under the write class a grant sets by default. Everything else the agent is allowed to call happens when it calls it, and what you review afterwards is the record of it.

          Granting happens at a terminal, and only at a terminal

          This is the one act the console cannot perform, and it is deliberately absent rather than missing. Granting mints authority: it creates the permission and signs it with the issuer key held on this machine. So the server publishes no grant route at all, not a disabled one and not a permissioned one. The moment granting were reachable over HTTP, the power to mint warrants would live in a network-reachable process, and the whole design rests on authority being minted by a human at a terminal. This console can read what exists and act on it. It cannot create authority.

          Grant one

          Run this in a terminal, in the repository you want the agent to work in:

          warrantor grant --goal "..." --tools git --write src --repo .

          Replace the quoted text with the job in one sentence: it is what every later review is read against. --tools git is the allowlist the broker refuses against. --write src records which paths are in bounds, and what that buys is containment rather than refusal: an out-of-bounds write is not blocked as it happens, it is simply never staged, so it never reaches your branch. Leaving --write off means no path is in bounds, not every path. --repo . is what creates the worktree; without it the warrant is still granted and still bounds staged effects, but there is no separate copy and the agent edits your working tree directly. Each warrant's own view says how strongly every bound is actually held.
