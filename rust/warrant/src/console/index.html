    Nothing has been granted on this machine yet

    A warrant is written, signed permission for an AI agent to do one stated job: what it is for, which tools it may use, which paths it may write to, and when the permission runs out. The agent works in an isolated copy of your repository, so nothing it does is visible outside that copy until a person settles the warrant, and external effects are staged rather than performed.

    Granting happens at a terminal, and only at a terminal

    This is the one act the console cannot perform, and it is deliberately absent rather than missing. Granting mints authority: it creates the permission and signs it with the issuer key held on this machine. So the server publishes no grant route at all, not a disabled one and not a permissioned one. The moment granting were reachable over HTTP, the power to mint warrants would live in a network-reachable process, and the whole design rests on authority being minted by a human at a terminal. This console can read what exists and act on it. It cannot create authority.

    Grant one

    Run this in a terminal, in the repository you want the agent to work in:

    warrantor grant --goal "..." --tools git --write src

    Replace the quoted text with the job in one sentence: it is what every later review is read against. --tools git is the allowlist the proxy refuses against. --write src records which paths are in bounds, and what that buys is containment rather than refusal: an out-of-bounds write is not blocked as it happens, it is simply never staged, so it never reaches your branch. Leaving --write off means no path is in bounds, not every path. Each warrant's own view says how strongly every bound is actually held.
