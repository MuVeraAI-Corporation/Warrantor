# proto/ — Canonical Protobuf contracts

The contract plane's machine-checked wire definitions. Managed by **Buf** (see repo-root
`buf.yaml`); breaking changes here break every language implementation.

## Layout

```
proto/
└── aumos/
    ├── identity/v1/      # I1 agent-identity (mock + real)
    ├── trust/v1/         # T1 trust-core sign/verify
    ├── evidence/v1/      # E1 flight-recorder AAR (P2)
    ├── attestation/v1/   # C1-1/C1-2 attestation reports
    └── protocols/v1/     # P1 AAE, P2 AAR, P3 CPE, ... (the 12 open protocols)
```

## Status

**Wave-1 (Phase 1) target.** The first proto schemas land as part of Phase 1 task 01:
`warrantor/identity/v1/agent.proto` (the **mock AgentVault** that Wave-1 components integrate
against), `warrantor/trust/v1/signing.proto`, `warrantor/protocols/v1/aar.proto`.

## What buf is used for

```bash
buf lint                                    # enforce STANDARD ruleset
buf breaking --against '.git#branch=main'   # reject breaking wire changes
```

**buf does not generate code in this repository, and there is no `buf.gen.yaml`.**

Rust bindings are generated by `rust/warrantor-api/build.rs` (tonic-build) into Cargo's `OUT_DIR`
on every `cargo build`. Nothing is committed and there is no manual regeneration step — the types
cannot drift from `proto/`, because they do not survive a `cargo clean`.

That is also why a `buf generate` targeting Rust must not be reintroduced. It would be a second,
competing generator writing to a directory that `lib.rs` does not `include!`, so its output would
be dead code that silently goes stale. A `prost`-only buf template additionally produces no tonic
service stubs, while `build.rs` sets `build_server(true)` and `build_client(true)` — the two
outputs are not equivalent.

### Other languages

Go, Python and TypeScript do **not** have generated bindings today. Where those languages need to
speak the contract, the structs are hand-mirrored and say so at the definition site (see
`go/agent-identity/service.go`). Generating them is planned work, and the config for it must scope
itself to those languages and leave Rust to `build.rs`.
