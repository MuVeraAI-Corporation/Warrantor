them preserves the class.

## Operational record — arm A, 2026-09-01

Kept because both problems below were invisible to the thing that was supposed to catch them, and
both would recur on arms B and C unchanged.

### The Modal lane had no checkpoints, and Modal preempts

Arm A died at **step 323 of 705** with `Container terminated due to preemption. Your Function will
be restarted with the same input.` It restarted **from step 1**. The run manifest said
`save_steps: null`, so there was nothing to resume from: the grant paid for 46% of a run twice and
kept none of it.

The cause was in the lane model, not in Modal. `save_steps` was derived **solely** from
`session_cap_hours`, which encodes "no deadline" as "cannot be interrupted". Kaggle has a hard 12 h
kill and got checkpoints; Modal has no cap, preempts anyway, and got none. The existing test was
even named `no_session_cap_means_no_save_steps` — the wrong contract, stated in the test name,
passing only because the lane it used happens to also be non-preemptible.

Fixed in `lanes.py`: `Lane` gained `preemptible`, `modal-a100` declares it, and a preemptible lane
without a cap now divides the **run** into ten checkpoints instead of dividing a deadline. Arm A's
second attempt ran to 705/705 without further preemption, so the fix is not yet exercised in
anger — B and C carry it.

### pytest was importing a different worktree

`warrantor_ml` is pip-installed **editable pointing at `M:\wt-2point1`**, another checkout. So
`python -m pytest` collected the test files from this tree and imported the module from that one,
and reported passes for code that never ran — including the regression test for a
`lora_target_modules` fix that exists only here.

It is not only pytest: every `warrantor-ml-*` console script is generated by that same install.
`warrantor-ml-publish` resolves to `M:\wt-2point1\...\publish.py`. An evaluation driven by the
console scripts would have measured another checkout's behaviour while looking entirely normal.

`tests/conftest.py` now prepends the sibling `src`, and `evaluate-arm.sh` drives `python -m` with
`PYTHONPATH` throughout. Check it in one line before trusting any run here:

    python -c "import warrantor_ml.lanes as m; print(m.__file__)"
