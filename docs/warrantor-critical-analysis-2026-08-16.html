1. Method — what was verified rather than read

This repository's documentation is unusually honest, which creates its own risk: it is trusted. So nothing below rests on a document. Each claim is one of three kinds, and they are marked:

KindMeans
verifiedObserved running, on this machine, this session.
readEstablished from the source, not executed.
unknownCannot be established from here.

The single most useful thing done was cheap: grep for every flag the code tells a user to pass. That found the defect the roadmap could not, because the roadmap can only record gaps somebody noticed.

2. What is genuinely real

verified The single-machine loop works end to end. A warrant is granted against a repository, a git worktree is cut, an agent runs under an OS-enforced lifetime link, tool calls traverse a policy engine, staged effects are hash-chained, a signed evidence bundle is written, and it verifies offline. That is not a demo — it is 515 passing tests over ~21,000 lines of Rust in the spine crate, with seven external dependencies and no async runtime. The small dependency surface on a security component is a real engineering achievement and is rarely held to.

verified The doctrine is load-bearing rather than decorative. Three separations are enforced structurally, not by convention:

  • Grant never crosses the wire. Minting authority requires a human at a terminal holding the issuer key. There is no HTTP route for it.
  • Verification happens only in Rust. Every viewer renders a verdict; none derives one. A second verifier could disagree with the first, and a human would then have to decide which to believe — the exact situation the product exists to prevent.
  • The agent endpoint does not publish lifecycle tools. Not denied — absent. A refusal can be misconfigured; a name that does not exist cannot be called.

read The distinction between Enforced, Mediated and Observed bounds is stated on every warrant and is accurate. write_paths and budget_cents_observed are observed and say so. Most products in this space would call all of it "enforced".

3. Five defects, and the evidence for each

3.1 The MCP proxy could not forward — and the error told you to pass a flag that did not exist

verified proxy::decide() has returned Decision::Forward since the proxy was written. The endpoint answered it with:

"{tool} is permitted by the warrant, but no upstream MCP server is configured
 to forward it to. Start the agent endpoint with --upstream <command>..."

--upstream appeared nowhere else in the binary. Grep returned exactly one hit: the sentence recommending it.

What it cost. Of everything an agent could ask a warranted session to do, four calls worked — the GitHub effects the staging registry knows how to queue. Every other permitted tool returned a failure whose remedy could not be performed. And tools/list published the warrant's tool names with {"type":"object","additionalProperties":true}: no properties, no required fields, so a model could not have composed a correct call even to a tool that worked.

Why it survived. It had a passing test. The test asserted that the arm returned an error. It did.

verified fixed A synchronous stdio MCP client (upstream.rs), tokio-free, with per-call deadlines from a reader thread. Live proof: selftest.echo round-tripped through the proxy, selftest.now was refused by the tools bound, the upstream's real JSON Schema was published, and the refusal was written to the store.

3.2 The shipped "integration" wrote security claims that were false

verified warrantor-harness config --agent claude_code wrote a CLAUDE.md containing:

Every action is recorded as an Agent Action Receipt (P2 AAR)
Secret exposure triggers kill-switch (invariant I-09)
File access is tracked and logged

Nothing in the system made any of those true. They are instructions to a model — a security boundary written into the context window while the substrate permits whatever it permits. That is the failure mode of all five frontier-lab intrusions in this repository's own README, and the reason the product exists.

This is a worse class than a missing feature. It is a false claim, generated by us, into the file the agent reads first, in a product whose entire value proposition is that claims about agent behaviour must be checkable.

verified fixed Replaced by warrantor agents: sixteen harnesses, each carrying real MCP client configuration and a coverage class naming what does not go through it. The Python generator still exists and has not been removed.

3.3 Two grants in the same second were one warrant

verified Warrant ids were format!("wrt_{:016x}", now().wrapping_mul(GOLDEN_RATIO)) — a bijection over a one-second clock. WarrantStore::save writes to a temp file and renames over the target, which succeeds silently when the target exists.

So two grants in the same second produced the same id, and the second replaced the first warrant's record: its bounds, its worktree pointer, and its staged-effect chain witness — the only place that warrant's staged effects could be found or checked. Nothing announced it. Scripting two grants, or typing them quickly, was enough. A model driving the MCP control endpoint is precisely the caller that grants twice in a second.

Found by a test that granted twice in a row and failed intermittently, depending on where the second boundary fell — which is why it had never been seen.

verified fixed Twice over, because the first fix is a probability argument and the second is not: ids now come from the system CSPRNG (same wrt_ + 16-hex shape, so nothing already printed changes), and WarrantStore::create refuses to write over an existing record at all, naming what would have been lost.

3.4 The guard ran at a context window no measurement was taken at

verified The Rust guard shipped num_ctx: 4096. Every published figure — 0.8152 adversarial recall, 0.0923 adversarial false-positive rate — was measured at 8192: evaluate.py's default, and what baselines.py records in both pinned baselines. That file's own opening line reads "num_ctx changes the number."

The consequence is not that the guard was worse. It is that nobody knew what it was, while the console, the roadmap and the CLI help all quoted the measured figures as though they described what was running. The parity discipline this repository applies rigorously to fine-tuned adapters — a promoted model must beat a baseline measured under a pinned configuration — was not being applied to the shipped one.

verified fixed MEASURED_NUM_CTX = 8192, pinned by a test that asserts against a literal. Asserting the constant against itself is exactly the test that would have kept 4096 green.

3.5 macOS could not paste, and the desktop agent could die behind a live window

read The Electron shell replaced the entire application menu with one custom submenu containing copy and selectAll — and neither paste, cut, undo nor redo. On macOS the standard editing shortcuts are delivered through the menu: a window without those roles cannot paste with ⌘V at all. The console has a token field. Replacing the menu also removed Hide, Services and the standard Quit item from an application with no other route to them.

Separately, the child's exit handler returned early once startup had settled — so a crashed or killed agent left a window rendering a console that could reach nothing, silently, because the console's recovery-when-the-agent-returns behaviour is deliberately quiet.

verified fixed Platform-correct menu with the Edit roles asserted on all three platforms; agent death now offers Relaunch or Quit; window geometry is remembered and sanitised against the displays that exist now (a position on an unplugged monitor is discarded rather than restored, which is the standard way an application becomes unopenable). Desktop tests 39 → 56.

4. The pattern underneath them

The roadmap already names it and had counted three instances: a component is built, is correct, and is not wired to anything that would exercise it. The ~20 substrate crates orphaned from the warrant; the guard benchmarked but never called during a run; the evidence archive with no client.

The forwarding gap is the fourth, and it is worse than the other three in one specific way that is worth isolating, because it generalises:

The other three were absences. This one was an absence with a test that made it look present. The test asserted the failure arm returned an error. It did. What no test asserted was that the error named a remedy the binary could perform — because "the error message is actionable" is not usually a testable property, so nobody writes it, so a message can rot for eight releases while the tests stay green.

The generalisation: every instruction this codebase gives a user is an untested assertion. Error messages, help text, README commands, the sentences in a verdict panel. The three defects above that were claims rather than code — the impossible flag, the CLAUDE.md, the quoted recall figure — all shipped for the same reason.

The cheap countermeasure, applied this session and worth institutionalising: a test that greps the binary's own output for the flags and commands it recommends.

Two further observations about how the defects were found, since the method transfers:

  • Three of five were found by writing tests, not by reading code. The grant collision surfaced as an intermittent failure in a test written for something else. Reading that id derivation would not have raised an eyebrow; running it twice did.
  • The lifecycle-tool check failed on its first target. A refusal was written for upstreams publishing settle — the obvious instance being this repository's own control endpoint. The first implementation split on . and took the last segment; the control endpoint publishes warrant_settle. It passed. A check that misses the one server it was written for is worse than no check, because it is believed. Only the test caught it.

5. The integration surface, classified by coverage

The registry's second column is the point of it. For every terminal coding agent, the honest answer to "is this agent bounded" is partly, and the previous surface said "every action is tracked".

The structural conclusion, which the table makes unavoidable: full mediation of a terminal coding agent is not achievable through MCP, by anybody, because those agents do not route their own file and shell tools through it. The strong cases are general assistants and SDK-built agents. For coding agents the correct claim is "bounded deadline, isolated worktree, staged external effects, signed evidence, mediated MCP tools" — and composing with a sandbox for the rest. That claim is defensible. "Every action is tracked" was not.

The one other honest gap in this layer

read An unknown tool's side-effect class is guessed. Anything the effect registry does not know is classified Read and forwarded — so an upstream write_file is forwarded rather than staged. Unchanged behaviour, but newly reachable, which makes it newly worth naming: the staging boundary covers four registered GitHub effects and nothing else.

6. Model intelligence — the honest state

verified The chain works. warrantor guard doctor, run against a live local Ollama serving Qwen3Guard-Gen-4B-GGUF:Q4_K_M, attached, resolved the model digest, and classified three probes correctly — including the jailbreak case that exists because the model answers Safety: Safe on line one and Categories: Jailbreak on line two, so a parser reading only the severity line lets every jailbreak through.

What that does not establish, and the command says so in its own output:

  • Three probes are not a measurement. The measured figures remain 0.8152 adversarial recall (≈ one adversarial case in five missed) and 0.0923 adversarial FPR (≈ one benign call in eleven flagged).
  • Those figures are why the guard observes and does not enforce. An enforcing guard at that FPR trains the operator to override it, and an operator who overrides twice stops reading it. The enforcement path exists behind a flag named so it cannot be typed by accident.
  • read Seven of the eight planned models are untrained, four of them cold-start blocked on real warrant history rather than on engineering.
  • read The weakest measured class, Unqualified Professional Advice at 0.4298 recall, is unreachable from WildGuardMix, which has no such category.
  • read One fine-tune has been run and the parity gate rejected it — correctly, and informatively: it diagnosed its own cause (the target vocabulary extinguished a third severity class and silently turned a documented policy knob into a no-op).

That rejection is the strongest single signal in this repository. A gate that rejects your own model is a gate somebody built to be believed.

7. Desktop and console

read The Electron shell is deliberately thin and should stay thin: it is a window, a child process and a policy. Its refusal to re-render anything is correct — a second viewer is a second thing that can misrender a verdict at the moment a human is deciding whether to release an agent's work.

verified The console's palette carried one good idea — a verdict must never be mistaken for chrome — whose consequences the CSS had not yet carried. Verdicts were encoded in colour alone. Roughly one man in twelve cannot reliably separate that green from that red, on the one surface where unknown and failed must never collapse into each other. Every verdict pill now carries a glyph as well as a hue (verified live in a browser), the verdict block takes a leading edge coloured from its own badge via :has() so the two cannot disagree, and release controls are deliberately plain — a filled primary button on settle would be a design that recommends the irreversible action.

verified The console gained the surface §2.2 needed and, for one commit, did not have: a custody section showing who acted, whether the hash chain holds, and where the warrant stands against its approval requirement — with a standing that has five kinds, because collapsing any two of them tells a reviewer they are done when they are not. The chain is checked server-side and reported as a value; a console that verified it too would be the second implementation of a check this codebase forbids everywhere.

verified Keyboard-first navigation — j/k/Enter/g/G, / to the filters, ? for a sheet generated from the same table the handler dispatches from, so the two cannot drift. Selection moves focus, which is how a screen reader is told which row the detail pane is showing. Plus aria-current, a live region that re-announces an identical consecutive message, and forced-colors handling that restores the pill borders Windows high-contrast would otherwise take along with the three verdict hues.

verified The desktop shell gained the two things a browser tab cannot do and nothing that duplicates the console: a tray presence, because a supervised agent runs for hours and a minimised window is how somebody forgets one is running; and native notifications when a warrant reaches held, which the console cannot raise because the renderer is granted no permissions at all. Both are pure functions: traySummary returns unknown rather than zero for an unreachable agent, and newlyWaiting notifies on transitions rather than levels — notifying on a level is how a person learns to dismiss notifications unread.

unknown No installer has been installed or launched on any machine. The packaging workflow has run green in dry-run and produced artifacts; nobody has downloaded one and double-clicked it. Installers remain unsigned, which means SmartScreen on Windows and Gatekeeper on macOS — and a security product that teaches a user to click through "developer cannot be verified" on first contact has taught them the wrong lesson. That is procurement, not engineering.

8. The backend — what shipped after this page was first written

This section originally read "the backend that is not there" and listed six gaps. Five of them are now built, and the shape each took is the interesting part: in every case the obvious implementation would have added a new trust root, and in every case it was refused in favour of something weaker that is honest about being weaker.

GapStateThe shape it took, and what it costs
Per-person identity (§2.2)built warrantor operator add <name> --scope read,stop,settle,approve --note "...". Tokens stored as SHA-256, printed once. Registry read per request, so revocation lands on the next request rather than the next restart. Every settle/void/stop/approve appends to a hash-chained actors/<id>.jsonl naming the operator — or null, never an invented name. The actor is now inside the signed envelope too — ReportBundle.custody carries the log's head digest, and editing who approved breaks verification. That needed no format bump: the bundle digest already covers every field, which was checkable and was not checked for two deferrals. Cost: a token authenticates a token, not a person — the name is bound out of band, and every rendering says so.
Approval routingbuilt approvals.json + warrantor approve. Gated on the CLI path as well as the API path — gating only the console would have made it decorative. The settler is not an approver by default. Anonymous approvals cannot satisfy a requirement above one, because one machine's terminal callers cannot be told apart. Void is never gated: discarding staged work is the safe direction.
Time anchoringbuilt A per-store append-only hash-chained ledger. Establishes relative order — if A precedes B, A was signed first, whatever timestamps either carries — and makes a backwards clock visible as its own kind of fault, because the remedies differ: a broken chain means somebody edited the file; a backwards clock means everything signed in that window carries a timestamp nothing can vouch for. Cost: it proves nothing about absolute time to anyone without an earlier copy of the head. No RFC 3161 authority is contacted — that would make every artifact depend on somebody else's key. The bridge is a human step: publish the head digest where something else keeps a clock.
Trust directorybuilt A carried signed file, not a queried service. One machine's pins signed by its issuer key, importable only against a key the importer had already pinned out of band. One out-of-band check buys everything that machine trusts; the root stays a key a human checked and only the fan-out improves. A local pin is never overwritten, imports are not transitive. Cost: no revocation channel, ever — a channel is a service. Bundles are dated snapshots and say so.
TLS (§2.3)built Feature-gated --tls-cert/--tls-key, verified at TLS 1.3. The reason it had been deferred was false, and that is the more useful finding: the objection was "a TLS stack in a seven-dependency crate", and rustls was already in the tree via ureq. The decision had been taken by a client dependency in a direction nobody wrote down, and the premise was checkable in one grep. A failed handshake gets no reply; the flags are both-or-neither; a build without the feature refuses them rather than ignoring them. Cost: no certificate is issued, renewed or checked for name, and it does not establish who the server is to a client — a self-signed cert is indistinguishable from an attacker's until pinned, and the startup line says so.
Bounds enforcement (§3.1)honest Unchanged and still correct as documented. No netns, no seccomp, no firewall. write_paths is observed and every warrant says so.

The pattern in how these five were built

Each had been listed as unbuilt for every release, and in each case the reason was the same: the textbook implementation is a service, and a service everyone queries sits above the Ed25519 signatures the product rests on. Identity wanted an IdP. Time anchoring wanted a timestamp authority. The trust directory wanted a key server.

The resolution was the same three times. Build the version that establishes less, name precisely what it establishes, and print what it does not under every rendering — a hash chain instead of a signature, relative order instead of absolute time, a carried file instead of a queried host. That is not a compromise reached for expedience: a weaker claim that is true is worth more here than a stronger one resting on infrastructure nobody audited, because the entire product is the proposition that claims about agent behaviour must be checkable.

9. What is actually left

Every engineering item on this page is done. What remains is not deferred work — it is two things engineering cannot produce, and one small one that can.

Not implementable from here, with the reason

  • Installing an installer. CI has produced all four platform installers green (run 31875701622), and desktop/test/packaging.test.js asserts everything a test can without a build: the config and the resolver agree on the binary name, the vendor directory is architecture-specific, the file list never reaches into node_modules, no publish channel is configured, the Windows install is per-user and never elevates, the macOS build is ad-hoc signed rather than signing-skipped, and Electron is on its audited pin. What is missing is a human downloading an artifact and double-clicking it on a machine with no warrantor on PATH. That is not automatable by definition — it is the test of whether the packaging assumption holds on somebody else's computer.
  • Four of the seven untrained guard models. They are cold-start blocked on real warrant history: the training data is refusal and guard signals from actual supervised runs, which accumulates only through use. No amount of engineering produces it. The other three need Modal GPU time against a $100 cap with ~$14 spent, which is a spend decision rather than a task — and the programme's own record includes a hypothesis (supervise_severity=False) that was proposed, run, and refuted by a 17-point recall drop, so running the next one uninstructed would be the same mistake with a different variable.

Genuinely a task, and small

Re-run the corpus benchmarks at the shipped configuration. The context window is in parity by construction now and guard bench makes parity checkable per machine, but the published 0.8152 / 0.0923 were measured before either was true. Almost certainly still correct; "almost certainly" is not the standard this repository holds its own adapters to.

The one-paragraph summary

The substrate is real, the doctrine is enforced structurally rather than by convention, and the single-machine loop is complete and well tested. What this session found is that the failures are concentrated not in the code but in the claims: a flag that did not exist, a generated file asserting protections that were not in force, a recall figure quoted for a configuration that was not running, and a warrant id that silently destroyed its predecessor. Each was invisible to the test suite because each was a statement rather than a branch. The code is more trustworthy than the sentences around it — which, for a product whose entire thesis is that claims about agent behaviour must be checkable, is the finding that matters most.
