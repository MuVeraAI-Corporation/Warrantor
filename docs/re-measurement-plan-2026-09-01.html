1. What I got wrong, and the real constraint

Correcting my own recommendation before acting on it

baselines.py says it in its own words: the pinned figures are measured “over the full held-out splits with no sampling”, stored as counts rather than rates, with a corpus digest over dataset identity and split file.

The constraint nothing can spend its way past

WildGuardTest has 341 adversarial positives. In total. That is the corpus. The 0.8152 adversarial recall is 278 caught of 341 — every one there is. ExpGuardTest has 1,256 positives, all used.

Halving a confidence interval requires roughly four times the sample. There is no fourth WildGuardTest. Running the same split again on an H100 produces the same 341 denominators, faster.

Compute buys repeated runs, additional conditions, and judging throughput. It does not buy statistical power on a fixed corpus, and a plan that promises otherwise is selling arithmetic that does not exist.

3. What compute actually buys

Four things, all real, none of them “more corpus”

WhatWhy it needs computeWhich paper it serves
Repeated runs at fixed configuration The reproducibility floor is a property of variance across runs. One run cannot measure it; ten can. This is the one place where more compute is more statistics. P1
Additional conditions on the same corpus Quantisation ladders, temperature settings, context windows — each is a full re-run of a fixed split. The corpus does not grow; the number of measured configurations does. P8, T-03
Alternative labelling regimes The gap [LayeredEns] §11.6 exposed: survivors depend on the labelling regime. Majority-of-N grader labels means N judge calls per item — the single largest token consumer here, and exactly what GlobalBatch is for. P6
Verification that the pinned baselines still reproduce Not new statistics — a regression test on published numbers. It is how a num_ctx drift gets caught in a day instead of eight releases. All

4. The five runs, specified

Ordered by value per token, with the stop condition for each

  1. R1 — Baseline reproduction (no new claim)

    What: Re-run all four pinned baselines at their recorded configuration — Qwen3Guard-Gen-4B-GGUF:Q4_K_M and the 0.6B, via Ollama, num_ctx 8192, seed 0, temperature 0, controversial_is_harmful=true, fail-closed.

    Success: counts match the pinned values exactly. Failure is the interesting outcome — it means something drifted, and finding that is worth more than the run costs.

    Compute: local. ~4,000 items across both corpora and both models. No cloud spend. This runs first and gates everything else.

  2. R2 — Replace the 8-case smoke bench

    What: The only genuinely under-powered figure. Build a real held-out case file — several hundred items drawn from the same distribution as the deployed traffic, not from WildGuard — so guard bench reports an interval a person can act on.

    Why it matters: at 7/8 the interval is [0.529, 0.978]. Any product decision made on that number is being made on nothing.

    Compute: local for the guard; batch for any judging of the new items.

  3. R3 — P6's labelling-regime check (the submission blocker)

    What: Re-run the §5.5b difficulty stratification under majority-of-N grader labels, matching [LayeredEns] §11.6's own regime, and report whether P6's 10-of-15 survives.

    Why it is first among the new work: P6 currently makes a mechanism claim — that association tracks training-family lineage — while its prior art explicitly declines a mechanism claim because survivors were regime-unstable. If P6's 10/15 is also unstable, the mechanism claim has the problem they backed away from. This is the difference between a submittable paper and a retraction.

    Compute: N judge calls per item on GlobalBatch. Largest token consumer of the five, and the reason batch exists.

  4. R4 — P1's reproducibility floor, properly replicated

    What: Ten identical runs at fixed configuration, measuring run-to-run verdict agreement. The one case where compute genuinely converts into statistics.

    Note: P1's figures sit at 0.9980–0.9993 — near ceiling. Distinguishing 0.9980 from 0.9993 requires large n and repeated runs, because at that scale a handful of flips moves the fourth decimal.

  5. R5 — P8's quantisation ladder at full split

    What: P8 currently runs at n = 1,000. Take it to the full split and add the deployed Q4_K_M rung explicitly, since that is what actually serves traffic.

    This is the one place “more n” is genuinely available — because P8 subsampled, unlike the baselines.

5. Pre-registration, and what it must include this time

Two lessons already paid for

Lesson 1 — register the significance test, not just the direction

A pre-registered monotonicity check once fired on a 0.1867 → 0.1600 dip and reported a reversal. McNemar on the same data: 2 worse, 4 better, p = 0.688. Noise, reported as a finding, because “is it monotone” has no notion of sample size.

Every ordering, trend or monotonicity claim in R1–R5 registers its significance test alongside it, with the paired form where items recur across conditions.

Lesson 2 — pre-registration says nothing about novelty

Every experiment in the last programme was frozen and hashed before its data existed, and a prior-art check afterwards still killed one paper and three claims. The literature check runs before the first draft, not after — and for R3 specifically, before the run, because the design is a response to someone else's §11.6.

What gets frozen before any run

  • The exact backend configuration, as a digest — model tag, quantisation, num_ctx, seed, temperature, top_k, top_p, and the controversial_is_harmful policy
  • The corpus digest over dataset identity and split file, so ExpGuard recall can never be scored against a WildGuard baseline
  • The slice definitions and their denominators
  • The hypothesis, the statistic, and the test
  • The stop condition — what result would make us abandon the claim
