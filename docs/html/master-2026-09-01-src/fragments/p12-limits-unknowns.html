Part 12

Honest limits, anti-goals, what is still unknown, and the answer to "how do we make sure this never happens"

This part states what the platform structurally cannot do, what it refuses to build, what the record does not settle, and what a board, an engineer and a supervisor can each be told without overstating. It exists because the product's whole proposition is that claims about agent behavior must be checkable, and a specification that overstates its own coverage refutes itself.

Every other part argues that something should be built; this one argues the other way. Three things usually blended are separated here: a limit is a property of the world that no engineering removes; an anti-goal is a capability we could build and deliberately will not; an unknown is a question the public record does not answer. Confusing them is how a governance program acquires a green dashboard and no defensible claim.

Design rule

A weaker claim that is true is worth more than a stronger one resting on infrastructure nobody audited. Internal S62 §15.5

The limits that will not go away

The specification's heading for this material reads "three limits" and its body carries five. The mismatch is left visible rather than quietly corrected, because it is a small instance of the defect class described at the end of this part: failures cluster in the prose, not the code. Internal S62 §13.1, §13.3 All five follow. The first two are standing doctrine, in the wording the platform is required to use everywhere.

Limit 1 — the mediation ceiling

Plain words. "Mediation" means every consequential action an agent takes passes through a component that can inspect, authorize, deny and record it. That component is the broker. The ceiling: for a terminal coding agent — one that works by driving a command line — full mediation is impossible, and not only for us. Every major terminal agent ships its own file, edit and shell tools that do not speak the tool protocol and therefore never reach the broker. Wiring one in buys mediation of the calls it makes through the protocol, nothing more. An agent granted a shell that runs a network client never touches the proxy. Internal S60

What the platform says instead of the impossible claim. Not "all actions are mediated." The defensible claim, used verbatim in spirit on every surface: bounded deadline, isolated workspace, staged external effects, signed offline-verifiable evidence, operating-system-enforced process lifetime, and mediated protocol tool calls — composed with a sandbox for writes and shell. Internal S62 §13.1 Full mediation is genuinely reachable in two configurations: general assistants whose only tools are protocol servers, and agents built on a software development kit where the warrant's server is the only toolset attached. Say which a given harness is, per harness, rather than letting the reader infer the stronger case.

This is why the scoreboard's first metric is effect coverage — the share of consequential effects that provably traverse the boundary, published rather than implied. Internal S62 §14

Limit 2 — there are three enforcement tiers, not two

Plain words. Products in this category label a control "enforced" or "observed." That split is one tier short, and collapsing it is how a false claim gets into a signed evidence bundle. The correct taxonomy has three tiers, and every rendering of a bound must carry its tier.

TierWhat backs itExamples todayWhat it survives
Tier ACryptography, or a guarantee of the operating systemDelegation depth; expiry via process-lifetime primitives; signature verification on receiptsA hostile agent — the bound holds whatever the agent does.
Tier BA chokepoint the call has to traverseTool admission; egress destinations; staged effect classesOnly calls that reach the broker. No network namespace, syscall filter or firewall sits in the supervision path, so a granted shell running a network client bypasses this entirely.
Tier CObservation and later reconciliationWrite paths and budget. Containment happens at settle, not at write.Nothing at the moment of action. The workspace keeps writes off the developer's tree and settle stages only declared paths, so out-of-bounds edits are never merged — a real property, but not refusal.

Two consequences. "Enforced" without a tier is not a claim, it is a mood. And the disclosure is a strength to sell rather than a weakness to bury: a competitor asserting uniform enforcement across all three is either wrong or has not looked. Internal S62 §13.1 The taxonomy is also configuration-dependent — one environment variable or trust-bundle change can silently downgrade a Tier A bound to Tier C, which is why configuration and secret material are claim-relevant surface under change control. Limit 3 — no new trust root, ever

Plain words. A "trust root" is the thing everyone must believe before anything else is checkable. Three capabilities here have textbook implementations that are network services: an identity provider for actors, a timestamp authority for time, a key server for the trust directory. A service everyone must query sits above the signatures the product rests on, placing the weakest link above the cryptography. All three shipped in the version that establishes less and names precisely what it establishes: a hash-chained actor log detectable to anyone holding a later head and proving nothing to a third party; a per-store ledger establishing relative order and a backward-clock fault, bridged to real time by a deliberate human step; and a carried signed bundle importable only against a key already pinned out of band, with no revocation channel because a channel is a service. Internal S62 §13.1

Generalized. When a feature seems blocked on infrastructure, ask what the weaker local version establishes and whether that is worth stating — then state the limitation in the code, the command-line output and the roadmap. This rule unblocked identity, anchoring and the trust directory, and is why none shipped as an unaudited dependency.

Limit 4 — software evidence cannot prove physical state

The effect-syscall table lists ACTUATE among nine consequential effect types, and an earlier draft asserted a kill path to a known-safe state for cyber-physical action. That is overstated and is corrected here. A receipt proves what the broker was asked to do and what it authorized. It cannot prove that a physical system reached a safe state, because the ground truth lives in sensors and actuators outside any cryptographic boundary we control. Internal S62 §13.1

So generic robotics and cyber-physical expansion is deferred until hardware and sector assurance partners exist. ACTUATE stays in the syscall table because the authorization half is real — non-delegable human authority, quorum issuance, an irreversibility class. The verification half is not ours to claim, and any deployment touching physical actuation must state which half it is buying. This bears directly on supervisory regimes requiring a demonstrable stop: the Gulf guidance note's immediate-shutdown expectation, with a September 2026 compliance point, is satisfiable for software effects and is a partner problem for physical ones. Supervisor · CBUAE S43

Limit 5 — the control-plane tax is the most likely way this fails

Not a security limit; a survival one, and more probable than any attack modeled elsewhere in this document. If the platform adds latency, review burden, integration cost and operating overhead faster than it enables autonomous work, teams route around it — and a control that is routed around provides negative security, because it also carries the belief that something is governed. Analyst projections of large-scale agentic-project cancellation describe this mechanism from the outside. Analyst projection S45

The discipline that follows is measurable: track time-to-value, reviewer load, bypass rate and a false-denial budget per workflow, carry a counter-metric for every metric, and retire any control whose benefit is not evidenced. A governance platform that cannot name a control it has killed is not measuring itself. Internal S62 §13.1

Four anti-goals: what this platform refuses to be

Each of these is buildable. Each is refused, and the reason is the same in every case — building it would either put us in a feature war we do not need to fight, or would dilute the one claim that is genuinely ours.

Anti-goal 1

Do not build a sandbox

Micro-virtual-machine and kernel isolation are mature and actively developed by far larger teams. Consume them behind a backend adapter and add the conformance profile that proves a given composition holds. The profile is the product; the sandbox is a dependency. This follows directly from Limit 2: because Tier B is a chokepoint and not a kernel boundary, containment is something we compose with rather than something we ship. Internal S62 §13.2

Anti-goal 2

Do not build an identity provider

Workload identity is a solved and graduated problem, and the standards work naming agent identity as foundational is public. Standard · NIST S16 Build only the delegation-intersection half — authority computed as the intersection across a chain of delegations — which the identity ecosystem does not provide and where the standards venue is still open. Standard · NIST NCCoE S14 Appearing as a peer to that ecosystem weakens the one claim that is ours.

Anti-goal 3

Do not build scanners or benchmarks

Red-team tooling, prompt-injection suites, agent-security benchmarks and evaluation harnesses exist and are good. This platform signs their output and binds it into a decision. It does not re-scan. The moment a competing scanner ships, the product is in a feature war against better-funded incumbents and has stopped doing the thing nobody else does. Internal S62 §13.2

Anti-goal 4

Do not claim the model is the control

No system prompt, policy document or instruction file may be described as a security boundary. This repository once shipped a generator that wrote context files asserting protections nothing enforced — instructions to a model presented as a boundary, the exact failure the product exists to refute. That generator is now a refusal that explains itself. Internal S62 §13.2

What the record does not establish

A fifth refusal, because buyers ask for it: this is not an alignment solution and cannot become one. Nothing here changes what a model is disposed to do. It changes what a model can express as an effect, what is independently denied, how far the residue reaches, and what can be proven afterward. Claiming to fix disposition would be the Anti-goal 4 error at a larger scale.

In plain words

"Chain-of-thought monitoring" means reading the model's written reasoning as it works and alerting on what it says. Useful, and not a boundary: the reasoning can become hidden, manipulated or absent, and an agent that spoofs a tool call is writing the record the monitor reads. A boundary denies the action; this reads the narration.

The investigation's limits propagate into this document

Because analysis was delegated to models of the same family as those in the incident, and coverage is a bit over 90% with a known spoofing rate above 7%, no behavioral finding here should be treated as forensically settled. The honest "never again" answer

Design rule

No serious architecture can guarantee that an incident will never occur, and any vendor who says otherwise has told you how much of their documentation to believe. The credible objective is defensible resilience, not an impossible zero-risk promise. Internal S61

What can be promised is five things, each of which is testable and each of which was absent or failed in the incident.

  1. Make unauthorized actions unexpressible or independently denied. Not discouraged: either the effect has no representation the agent can construct, or something that is not the agent refuses it.
  2. Bound the residual blast radius. Assume the first objective fails. Authority, destinations, credentials, lifetime, delegation depth and commit scope each cap how far the failure travels.
  3. Detect cross-layer deviation at machine speed. The incident's detectors fired; separate teams and systems did not correlate them into a sufficiently severe cross-system incident soon enough. Correlation is the control, not collection. Internal S65 §2
  4. Halt before external harm. A stop reaching a known-safe state for software effects, revocation propagation measured rather than asserted, and the physical case excluded per Limit 4.
  5. Produce independently verifiable evidence. Signed, offline-checkable by a third party holding no privileged access to our systems — the one differentiation claim that survives contact with the 2026 market.

Two further objectives follow, and buyers ask for them by name: reconstruct what happened independently rather than from the operator's account, and prove remediation before restoring service.

Three sentences, written out

Drafted to be said aloud without qualification and without overstating. The same claim at three altitudes.

A chief information security officer, to the board

The sentence

"We cannot promise this class of incident will not happen to us, and no architecture can; what we can do is show, on demand and without asking you to take our word for it, which of our agents' consequential actions were authorized in advance, which were denied, how long any remaining exposure lasted, and that the evidence for all of it was produced somewhere our agents cannot reach."

An engineer, in a design review

The sentence

"That bound is Tier B — it holds only for calls that traverse the broker, so it does not hold for anything the agent runs inside the shell we just granted; if this control has to survive a hostile agent, it needs to be Tier A or composed with a sandbox, and either way the receipt has to render its tier."

A supervisor or examiner, on the record

The sentence

"Every consequential action taken by an agent in this system carries a signed record that your examiners can verify offline with no access to our infrastructure; each record states which limits were enforced by cryptography or the operating system, which by a mediating chokepoint, and which were only observed; and we can demonstrate the stop path and produce the reconstruction of any run without depending on the vendor whose system is under review."

The supervisory framing is deliberate. Revised interagency model risk management guidance of 17 April 2026 supersedes the prior letters and places generative and agentic models outside its scope, with separate guidance promised. Supervisor · Fed / OCC S39 That is a deferral, not an exemption: obligations attached to the underlying action are untouched, and the separate guidance will be written against whatever the industry has already built. The Gulf guidance note carries audit rights and an immediate-shutdown expectation with a September 2026 compliance point Supervisor · CBUAE S43, and India's supervisory line on lending requires a human override path Supervisor · RBI S41. None is satisfied by a policy document; all three are satisfiable by a receipt that names its enforcement tier.

What would falsify this document

The central abstraction here is that agent authority is an operating-system problem — effects as syscalls, warrants as authority, receipts as the record. That is a claim, and claims that cannot fail are not claims. Six observations would show it wrong.

  1. Effect coverage stays near zero in real deployments. If teams keep granting shells and the measured share of consequential effects traversing the boundary never rises meaningfully, the syscall abstraction is an optional side channel, and the mediation ceiling is the whole story rather than a limit within it.
  2. A conformance profile passes while an escape suite still succeeds. Anti-goal 1's composition argument rests on the profile being a real test of a real composition. One clean escape against a passing profile falsifies the profile.
  3. Receipts verify and investigators still cannot reconstruct. If a signed, complete chain does not shorten an investigation against a realistic adversary, the evidence model captures the wrong things and cryptographic integrity has been mistaken for investigative sufficiency.
  4. A second implementation cannot verify the first's bundles. Offline third-party verifiability is the differentiation claim. Until an independent implementation checks our bundles it is a claim about a file format, not a property. Today the verifier count is one.
  5. The delegation-intersection primitive gets solved by the identity ecosystem. Anti-goal 2 bets this half is not coming from the identity vendors, and standards work currently names it unsolved. Standard · NIST NCCoE S14 If it ships there, rewrite this document rather than defend it.
  6. The control-plane tax exceeds the autonomy unlocked. Rising bypass rates, reviewer fatigue and workflows quietly routed around the platform falsify the value argument even if every security claim holds. The most likely falsifier, and the easiest to measure. Internal S62 §13.1

The communication rule

Across eight recorded claim-defects on a single branch, the failures clustered in the prose rather than the code, and were invisible to a suite of several hundred tests. An error message told an operator to pass a flag that existed nowhere in the binary, and survived eight releases with a passing test — because the test asserted the branch returned an error, and it did. A quoted recall figure described a context length the product did not run at. Internal S62 §13.3

Three checks, cheap and with a demonstrated hit rate, run before any claim in this document is repeated publicly:

Check 1 · Dispatch
Every flag or command recommended in an error message or help text is actually dispatched by the binary.
Check 2 · Configuration
Every quoted metric is checked against the configuration that produced it. Context length, seed and quantization each move the number, so a figure without its configuration is not a figure.
Check 3 · Cross-document
Every status claim is checked against the other document that records the same fact. A correction can introduce its own error by understating, which has happened here — and understating is not the safe direction.

The rule that generalizes from all three, and that governs how limits are disclosed rather than merely acknowledged: no console, report, score, sales page or compliance pack may collapse "observed," "advisory," "mediated" and "enforced" into a single green status. Commercial trust depends on preserving those distinctions precisely when preserving them lowers the apparent score. Internal S61 The highest-leverage place to enforce it is the moment before a run starts, where the person launching it sees in ordinary language what the agent may do, what it may reach, what is irreversible, and which limits are enforced rather than merely observed.
