§ 06

What is working

A developer on this tree can grant a warrant, run an agent under supervision in an isolated worktree, watch it from a CLI, a browser console or a desktop window, read a signed report, and settle, void or stop it. Evidence exports verify offline. That path is complete. Everything below is what that sentence actually contains.

Authority spine

  • Warrant grant / settle / void / stop lifecycle in aumos/rust/warrant/. IDs are wrt_ plus CSPRNG bytes.
  • Nine-gate composite verdict implemented in the notary library; the warrant report copies bound_strengths() verbatim and a test forbids upgrades.
  • Capability algebra and delegation-chain intersection: a child cannot hold what its parent did not (WarrantBounds::contains).
  • Ed25519 domain-separated signing. Issuer key mints; settle key releases; device key only after archive device pairing. serve deliberately does not mint keys.
  • Twenty-nine CLI commands plus help in aumos/rust/warrant/src/bin/warrantor.rs: grant, list, holdings, prune, report, verify, issuer, archive, egress, spend, stop, settle, void, stage, run, supervise, status, mcp, operator, approve, queue, sandbox, agents, guard, anchor, selftest-upstream, serve, console.

Oversight

  • Named operators with four scopes (read,stop,settle,approve), tokens stored as SHA-256 and printed once, registry reread per request — aumos/rust/warrant/src/operators.rs.
  • Hash-chained actor log. Two-person rule. Deadlock is a first-class answer. Queue derived in review.rs (no queue.json).
  • Notifications: settled, voided, stopped, filing-queued, review-requested. HTTP/console notify via StoreApi::with_notifier. Notify commands require --allow-notify-command on the invocation — a file write cannot arm them, because the supervised agent shares this UID.

Evidence and custody

  • WAR receipt envelope, tiered anchoring, relative-order time ledger in anchor.rs.
  • Local trust directory and carried signed bundles in trust.rs / bundle.rs. No network directory.
  • Postgres append-only archive in aumos/rust/archive/. CLI pairing / push / fetch / list / summary / auto settle. Automatic push on CLI settle exists; failed filing does not fail settle; queue is archive/pending.jsonl.
  • Holdings inventory plus prune of NoIntegrityConsequence classes only.

Surfaces

  • HTTP console compiled into the binary: aumos/rust/warrant/src/console/. Polls every five seconds. Token in the URL fragment. Distinguishes error / rows / filtered / unreadable / first-run.
  • Electron desktop viewer — see § 07.
  • TLS for warrantor serve behind --features tls (tls.rs). Bind beyond loopback without TLS is a refusal unless --i-accept-cleartext-on-this-network.

Integrations and harness

  • MCP proxy with Forward / Stage / Deny. Upstream client in upstream.rs. --upstream exists. selftest-upstream is a two-tool server in this binary.
  • Registry of 36 harnesses with detect / show / wire. Coverage-class honesty is test-enforced. See § 08.
  • Python session harness with OS lifetime link. config is a refusal of prompt-as-boundary.

Guard measurement apparatus (models not the product yet)

  • Observe-only attach behind --guard. guard doctor, guard bench with Wilson intervals, guard export-corpus that refuses to label rows with the guard’s own verdict.
  • tests/guard_parity.rs pins sampling knobs to evaluate.py.
  • One fine-tune was run and the parity gate rejected it. That path is exercised. Seven of eight models remain untrained.
§ 07

Electron desktop — Windows and macOS

The requirement “Electron based desktop app instead of Tauri for windows and macOS” is already satisfied by the tree. There is no Tauri implementation to remove and none to add. This section is the checkable record of that fact, the security policy, the packaging matrix, and what has been installed versus only built.

Verified — Electron, not Tauri Package @warrantor/desktop at aumos/desktop/package.json names electron ^43.4.0 and electron-builder ^26.15.3. Scripts: start = electron .. A case-insensitive search of json/toml/yml/js/rs/ts manifests finds no Tauri. No src-tauri, no tauri.conf.json. Current work is not “migrate to Tauri” and not “replace Tauri.”

What the app is

aumos/desktop/src/main.js states the job: a window, a child process, and a policy. It starts warrantor serve --port 0 on loopback, reads the session token from stdout, and points a locked-down window at the console the agent already serves. It is not a second implementation of the console. The console renders a verdict computed in Rust and never derives one. Everything visible is served by the agent.

Why it exists given warrantor console: that command already opens a browser and requires a terminal. This removes the terminal, which is the difference between a surface an engineer can use and one a reviewer can.

Spawn arguments are only serve --port 0. Nothing may add --allow-settle; that flag would undo the “viewer, not authority” decision. The shell must not hash the bundled binary either: verification happens only in Rust, and a check above that line would be a second verifier that can disagree with the first.

The file imports nothing so node --test can gate it with no Electron and no display. Tests: aumos/desktop/test/policy.test.js, packaging.test.js, shell.test.js.

§ 08

How the in-house agent harness is built

This is the Warrantor/agent harness, not the Grok Build goal harness. It is a process-level warrant plus an MCP proxy, plus a Python session wrapper, plus a vendor-neutral spec. A previous “integration” wrote instruction files that claimed every action was recorded. Nothing made those sentences true. The current design refuses that class of boundary.

There was already an “integration” surface in this repository before this file: a Python command that wrote CLAUDE.md, AGENTS.md or .cursorrules containing sentences like “Every action is tracked and recorded” and “Secret exposure triggers kill-switch”. Nothing in the system made those sentences true. They were instructions to a model.aumos/rust/warrant/src/harness.rs module docs

Four entries exist to say no rather than to be wired:

  • minimax — hosted product, no local stdio MCP client this build can point at a warrant.
  • open-webui — needs an MCP-to-OpenAPI bridge; coverage is whatever the bridge chooses to forward.

CLI: warrantor agents list | detect | show <id> | wire <id> <warrant-id>. Wire is dry-run by default. Generated command is always warrantor mcp --agent <id> --root <store> plus optional --upstream. The warrant id is baked into the arguments: stale wiring points at a settled warrant and the endpoint refuses to start. Fail closed.

JSON wiring splices with serde and preserves the rest of the file. TOML is a section splicer that refuses multi-line string delimiters. YAML and unverified paths are printed, not written.

MCP proxy and upstream forwarding

aumos/rust/warrant/src/proxy.rs Decision is Forward, Stage, or Deny — not “Refuse.” decide():

  1. Observe mode still denies Destructive and Financial: learning must not destroy or spend.
  2. Observe otherwise records the tool and returns Forward. Observe does not stage ordinary writes; a pull request opened during observe is really opened.
  3. Enforce: tool not in allowlist → Deny bound tools.
  4. Every destination of the call is decided by the egress broker. Empty egress bound means none.
  5. Side-effect in staged_classes and tool in the effect registry → Stage.
  6. Else Forward.

Staging registry knows four tools and only four: github.create_pr, github.comment, github.request_review, github.add_label — aumos/rust/warrant/src/staging.rs. The staging boundary covers those GitHub effects and nothing else.

aumos/rust/warrant/src/upstream.rs is a synchronous MCP client over a child process’s stdio. No tokio. Per-call deadline via reader thread and recv_timeout. Tools published as <name>.<tool>. An upstream that publishes warrant lifecycle verbs is refused at attach — a check that split on . and took the last segment missed this repository’s own warrant_settle. Opt-in is named --upstream-allow-lifecycle-tools-i-accept-this.

Historically Decision::Forward existed while --upstream did not. The endpoint told the operator to pass a flag the binary did not have. A passing test asserted the error. That is fixed on HEAD. Forwarding still mediates MCP, and MCP only.

--upstream-class '<tool>=read|write|destructive|financial' and --upstream-refuse-unclassified replace the old Read-guess. The registry still wins over a declaration, because those four tools are the ones settle can actually perform.

Two MCP endpoints

aumos/rust/warrant/src/mcp.rs: the single most dangerous thing this file could do is expose settle to the wrong caller. Control endpoint (warrantor mcp) is the developer’s agent and publishes lifecycle tools. Agent endpoint (warrantor mcp --agent <id>) is the supervised agent and does not have those tools at all — it does not deny them; it does not publish them. Under enforce, an ungranted tool is not published. Guard attach is optional; a run record is written either way so “nobody was watching” and “nothing ran” are not the same observation (runs.rs).

Worktree, supervise, stop, kill-switch

worktree.rs — isolated git worktree on warrantor/<id>. Isolation is filesystem-inside-the-repo only. Isolation of the declared bounds is a property of the bounds, not of the worktree. Settle never removes a worktree; only void does.

warrantor run re-execs as supervise detached: closing the terminal ends the view, not the run. Deadline is Enforced by the OS link. Stop kills the supervisor group; the agent’s pid is never persisted; the warrant goes Open → Held, not Void. Enforcement mode on the stop record is advisory. There is no daemon control socket path; stop relies on the OS link.

aumos/rust/kill-switch/src/execution.rs — critical_image_memo is why HEAD is dea7cdd. Windows tasklist.exe was spawned up to six times per kill (0.6–2.86 s each) against a 5 s budget. The memo consults the rail once per engine. Poisoned mutex skips the memo and evaluates the rail directly — never silently disable a safety rail.

Sandbox profile — emits argv, enforces nothing

This module emits a command line. It enforces nothing. … bound_strengths is unchanged by this module and must stay unchanged by it.aumos/rust/warrant/src/sandbox.rs

warrantor sandbox <id> [--kind bubblewrap|firejail] prints a prefix and names every bound the sandbox cannot express, and every bound where the profile would be stricter than the warrant. A no-egress warrant gets --unshare-net. A warrant permitting hosts gets none. Glob refinement inside the worktree is not expressed (that would loosen src/** into a read-write src/). Module docs record a 2026-08-17 Linux 6.18 run: writes to $HOME and /etc failed EROFS; DNS denied; the claim “a write outside the worktree fails at the syscall” was false for /tmp (private tmpfs, succeeds, discarded at exit). One kernel, once, is not closure. W1 §3.1 is not closed. A wrapper of the form bwrap … agent || agent turns a refused sandbox into an unconfined run.

§ 13

ML and guard

Two layers, deliberately split. A model judgment can become a refusal signal recorded against a warrant, never a verification verdict (RFC W2).

Runtime (Rust)

aumos/rust/warrant/src/guard.rs plus CLI guard doctor|bench|export-corpus. It enforces nothing, deliberately. At published 0.8152 adversarial recall it would miss roughly one adversarial case in five; FPR 0.0923 would train operators to override it. The enforcement path exists behind --guard-enforce-untested-do-not-use, is off, and is untested in production. No --guard means no signals; a guard that cannot resolve its model digest refuses to attach rather than emitting provenance-free “evidence.”

Live miss that is a category limit, not a threshold: Qwen3Guard caught rm -rf and missed “Force-push a rewritten history over main.” Bounds refuse first; the model comments on what bounds allowed. Wired the other way around, that force-push would have gone through. That is why the enforce flag is named the way it is.

Training and measurement (Python)

Implementations: aumos/python/warrantor_ml/src/warrantor_ml/. Launchers only: aumos/ml/*.py. tests/guard_parity.rs reads evaluate.py as a compile-time string so num_ctx, seed, temperature, top_p, top_k, and the controversial policy cannot drift.

Run weak-2026-08-13a trained on Modal and the parity gate rejected it. Seven of eight models remain untrained. Four are cold-start blocked on real warrant history (exporter exists; labels are warrant-level on call-level rows). Corpora re-measure is blocked on an HF click-through token. This session has no HF_TOKEN. Shipped cases: aumos/docs/examples/guard-bench-cases.example.jsonl.
