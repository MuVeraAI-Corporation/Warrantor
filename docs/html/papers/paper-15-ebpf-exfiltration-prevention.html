Abstract

An LLM agent that has been prompt-injected or otherwise subverted seeks, characteristically, to exfiltrate — to send sensitive context (secrets, internal data, the conversation itself) to an attacker-controlled endpoint via the same network egress the agent legitimately uses for tool calls. Application-layer monitoring misses this because the egress is policy-compliant in form; the malice is in the content and the destination, observable only at the system boundary. eBPF — the in-kernel programmable filter that powers modern cloud-native runtime security (Tetragon[1], Falco[2]) — offers the boundary observability that application monitoring lacks, and the recent AgentSight work[3] demonstrates eBPF "boundary tracing" specifically for LLM agents, correlating agent intent with system effects at <3% overhead. We present an eBPF-based exfiltration-prevention policy framework for LLM agents, built on the Tetragon/Falco enforcement model and the AgentSight observability model, in which the agent's outbound network is policy-gated at the kernel, anomaly-correlated with the agent's declared intent, and integrated with the kill switch (Paper 14) for automated containment.

§1. Introduction: the exfiltration primitive

Exfiltration is the terminal step of most agent compromises: an injected instruction directs the agent to send sensitive data out, and the agent does so via the same HTTPS egress it uses for legitimate tool calls. The egress is, in form, entirely policy-compliant — the agent is permitted to make outbound network calls, and it is making one. The malice is invisible to any monitor that checks only "did the agent make a permitted call?" It is visible only at the system boundary, where the destination (an attacker domain) and the content (a secret, a payload) can be observed and correlated with the agent's declared intent for the call.

§2. Background: eBPF runtime security

eBPF (extended Berkeley Packet Filter) allows safe, in-kernel programmable hooks on syscalls, network events, and kernel tracepoints, with negligible overhead. It is the substrate of modern cloud-native runtime security: Tetragon[1] (Isovalent/CNCF) provides real-time policy enforcement at the kernel layer; Falco[2] (CNCF/Sysdig) provides a syscall-level rules engine for detection. The Oligo security use-case survey[4] explicitly identifies data-exfiltration detection as a core eBPF use case via irregular syscall/network patterns. These tools are mature for generic workloads; their application to LLM agents specifically is new.

§3. Why application-layer monitoring fails

Application-layer monitoring (instrumenting the agent framework) fails for three reasons. (1) It trusts the agent runtime, which is precisely what is compromised. (2) It sees the tool-call payload but not the underlying socket — an agent can tunnel exfiltration through a permitted tool. (3) It is framework-specific; an agent moving between LangChain, AutoGen, and MCP breaks the instrumentation. eBPF, running in the kernel below and independent of the framework, sees every outbound socket regardless of how the agent produced it.

§4. The eBPF policy framework

The framework enforces a network-egress policy at the kernel (Tetragon-style): the agent process may connect only to a declared allowlist of tool endpoints; any other destination is blocked and logged. Content inspection (where the TLS can be terminated, e.g., in a boundary proxy) adds a payload check: outbound content matching secret-patterns or exceeding a declared data-volume budget is blocked. Both feed the anomaly pipeline.

§5. Intent–effect correlation

The AgentSight contribution[3] is the correlation of agent intent (what the agent declared it would do, observed via TLS interception of the LLM call) with system effects (the eBPF-observed syscalls and network). A divergence — the agent declared a benign action but produced an exfiltration-pattern syscall stream — is the high-signal anomaly that pure network monitoring cannot produce. We adopt this correlation: the eBPF policy blocks the egress, and the intent–effect divergence triggers the kill-switch composition (Paper 14).

§8. Conclusion

eBPF provides the kernel-layer boundary observability and enforcement that application-layer agent monitoring cannot. Composed with AgentSight's intent–effect correlation and the kill switch, it forms a defense that catches exfiltration attempts invisible to form-compliant application checks, at <3% overhead, framework-agnostically.
