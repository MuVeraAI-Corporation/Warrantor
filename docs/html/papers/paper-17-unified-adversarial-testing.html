Abstract

The LLM red-teaming ecosystem has matured rapidly into a set of strong, independent tools — HarmBench[1] (ICML 2024), JailbreakBench[2] (NeurIPS 2024), garak[3] (NVIDIA), PyRIT[4] (Microsoft) — each with its own test-case schema, target adapter, and verdict format. The result is fragmentation: a vulnerability found by one tool does not transfer cleanly to another, a defense evaluated against one is not comparable to a defense evaluated against another, and the central empirical finding of HarmBench — that no single model defended against all 18 attack methods — is hard to build upon when every team uses a different subset. We present a unified adversarial-testing framework (the Open Harness, X3) that normalizes the test-case schema, target adapter, and verdict format across the major tools, so a test authored for one runs against any model and a defense's results are comparable across the ecosystem. We report the interop achieved across HarmBench, JailbreakBench, garak, and PyRIT, and argue that unification is the structural prerequisite for the field's empirical progress.

§1. Introduction: a mature field, a fragmented tooling

LLM red teaming has, in two years, gone from ad hoc prompt collections to rigorous standardized frameworks. HarmBench[1] compared 18 attack methods across 33 target models and found no single model resisted all attacks — a foundational empirical result. JailbreakBench[2] established a fixed behavior set and artifact repository for reproducibility. garak[3] and PyRIT[4] provide the probing and dynamic-attack infrastructure. The field's maturity is real; its fragmentation is also real, and fragmentation blunts the maturity's value.

§3. The comparability problem

Each tool's schema, adapter, and verdict format differ. A test case in HarmBench does not run in garak without manual translation; a "jailbreak success" verdict in PyRIT is not identical to one in JailbreakBench. The consequence: results reported for one framework do not transfer to another, and the field's empirical progress is slower than the maturity of its individual tools would suggest. The comparative survey[5] documents the divergence in detail.

§4. The Open Harness (X3) design

The Open Harness defines three normalizations: (1) a canonical test-case schema (behavior, prompt, expected-verdict-policy, metadata) into which each tool's cases are translated; (2) a target adapter interface (send prompt → receive response) that abstracts the model backend; (3) a canonical verdict format (attack-succeeded/failed/inconclusive + evidence) with a per-tool verdict-translator. A test authored once runs against any model via the adapter; a defense's results are comparable because the verdict is normalized.

§5. Interop across the four tools

We implement translators for HarmBench, JailbreakBench, garak, and PyRIT, and verify that a fixed test corpus produces consistent verdicts when run through each tool's native path versus the unified path. Discrepancies (where a tool's native verdict differs from the normalized one) are documented and, where they reflect genuine scoring-philosophy differences, surfaced as configurable policy rather than silenced.

§8. Conclusion

The red-teaming field's individual tools are mature; its fragmentation blunts that maturity. The Open Harness unifies the schema, adapter, and verdict across HarmBench, JailbreakBench, garak, and PyRIT, making tests transferable and defenses comparable — the structural prerequisite for empirical progress. Paper 23 develops the harness as an OSAF specification.
