Abstract

Two distinct isolation primitives protect an AI agent's runtime: sandboxing (seccomp, namespaces, WASM), which constrains what the agent can do, and trusted execution environments (AMD SEV-SNP[1], Intel TDX[2]), which constrain who can observe the agent. They are deployed independently today, leaving a gap: a sandboxed agent on an unattested host can be observed by the host, and an attested agent without a sandbox can do anything the TEE permits. We present cryptographic sandbox boundary attestation — a composition in which the sandbox configuration (the syscall filter, the namespace layout, the network policy) is measured and carried in the TEE attestation, so a relying party can verify both that the agent runs sandboxed and that the sandbox runs in a confidential VM. We formalize the composed boundary property, show it closes the gap each primitive leaves open, and note the composition with confidential containers on bare metal[3] as the deployment substrate.

§1. Introduction: two isolations, one gap

Sandboxing and confidential computing answer different questions. Sandboxing answers "what is the agent permitted to touch?" — it constrains the agent's syscalls, network, and filesystem. Confidential computing answers "who is permitted to observe the agent?" — it protects the agent's memory from the host. A defense that uses only one leaves the other question open: a sandboxed agent on a plain VM is observable (prompt-injection reconnaissance, gradient theft); an attested agent without a sandbox is unconstrained (the agent can do anything the TEE permits, including exfiltration). The composition — a sandboxed agent in an attested TEE — closes both, but only if the relying party can verify both in one attestation.

§2. Background: sandboxes and TEEs

Agent sandboxing primitives: seccomp-bpf (syscall filtering), Linux namespaces (mount/pid/net isolation), WASM (capability-based runtime). TEE primitives: AMD SEV-SNP[1] (Secure Encrypted Virtualization with attestation reports) and Intel TDX[2] (Trust Domain Extensions). The Red Hat confidential-containers-on-bare-metal work[3] demonstrates the deployment substrate that composes these for containerized workloads — the natural host for an agent runtime.

§3. The composition gap

The naive composition — sandbox the agent, then run the sandbox in a TEE — is insufficient because a relying party verifying only the TEE attestation learns nothing about the sandbox. The agent could be running unsandboxed inside a perfectly attested TEE, and the relying party would have no way to tell. The fix is to make the sandbox configuration part of the attested measurement: the TEE's launch measurement must include the syscall filter, the namespace layout, and the network policy, so the attestation proves both the TEE boundary and the sandbox boundary in a single verifiable artifact.

        (a) TEE is genuine, debug off, fw floor met

        (c) both in one signed report

§5. The composed boundary property

Theorem (Composed Boundary)

Under the boundary-attestation design of §4, a relying party that verifies the attestation against a policy P can conclude both (a) the agent runs inside a TEE whose memory the host cannot observe (confidentiality), and (b) the agent runs inside a sandbox whose configuration matches P (containment). The two compose: a host adversary cannot observe (by the TEE), and the agent cannot exceed P (by the sandbox), and neither property can be defeated without breaking the attestation.

§6. Implementation and the measurement

The sandbox configuration is captured as a canonical-CBOR document (the syscall-filter rules, the namespace mounts, the network policy) and its hash is bound into the confidential VM's launch measurement (via a measured-boot stage that hashes the initramfs carrying the sandbox). The attestation thus reports M(boot) ⊕ M(sandbox_config); the relying party, knowing the expected sandbox policy, verifies both. Implementation uses confidential containers[3] on SEV-SNP/TDX as the host, with the AumOS R-pillar providing the sandbox policy.

§9. Conclusion

Sandboxing and confidential computing answer different questions; the composition — with the sandbox configuration measured into the TEE attestation — answers both in one verifiable artifact. This is the boundary primitive that makes an agent runtime defensible against both the host adversary and the unconstrained agent.
