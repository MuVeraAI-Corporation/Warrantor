Specification Abstract

This document specifies the Open Harness Specification (OHS), built on AumOS's open-harness-spec (X3), as a vendor-neutral specification for agent testing harnesses — defining the canonical test-case schema, the agent-interface adapter, the verdict-reporting format, and the reproducibility-packaging requirements (Paper 17). The OHS lets a test authored for one agent framework run unchanged against any other, addressing the reproducibility crisis in agent evaluation where results reported for one framework do not transfer to another. The specification aligns with the Model Context Protocol (MCP)[1] as the agent-tool protocol its adapters target, and adopts OpenSSF Model Signing's reproducibility-pack conventions. Reference adapters cover the major frameworks (LangChain, AutoGen, OpenAI Agents, MCP); a seed test corpus is contributed by the OSAF community.

§1. Introduction and status

This OSAF specification generalizes the Open Harness of Paper 17 into a vendor-neutral testing-framework standard. It addresses the reproducibility crisis in agent evaluation: results reported for one framework do not transfer to another, because every framework has its own test schema, adapter, and verdict semantics. The OHS normalizes the three so a test authored once runs anywhere, and a defense evaluated under OHS is comparable to any other.

§2. Alignment with the Model Context Protocol

The Model Context Protocol (MCP)[1] — Anthropic's open, vendor-neutral JSON-RPC protocol for connecting LLM/agent applications to external data sources and tools, donated to the Agentic AI Foundation in 2026 — is the agent-tool protocol the OHS adapters target. Because MCP standardizes the agent↔tool interface, an OHS adapter that drives an MCP-conformant agent is portable across every MCP-conformant runtime. The agent-interoperability survey[2] characterizes MCP and its alternatives; the OHS chose MCP as the alignment target for its openness and adoption.

§3. Normative: test-case schema

The canonical test-case schema (behavior, prompt, expected-verdict-policy, metadata, probe-source) into which each tool's cases (HarmBench, JailbreakBench, garak, PyRIT — Paper 17) are translated. The schema is normative; translators are informative (tool-specific). A conformant harness MUST accept the canonical schema and MAY accept tool-native schemas via documented translators.

§4. Normative: agent-interface adapter

The adapter interface: send(prompt) → response, abstracting the model/agent backend. Conformant adapters exist for the major frameworks; the MCP-aligned adapter is the reference. An adapter that distorts the agent's behavior (e.g., by preprocessing the prompt in a way that changes the attack surface) is non-conformant.

§5. Normative: verdict format

The canonical verdict (attack-succeeded/failed/inconclusive + evidence + judge-metadata). Verdict-translators map tool-native verdicts to the canonical one; genuine scoring-philosophy differences are surfaced as configurable policy, not silenced.

§6. Normative: reproducibility packaging

A test run produces a reproducibility pack: the test case, the adapter version, the agent/model identifier and version, the verdict, and the full transcript — signed and archivable. The pack adopts OpenSSF Model Signing conventions so a published result is independently reproducible. This is what closes the reproducibility gap: a result claim is a pack, verifiable by re-running it.

§7. Path to standardization

OSAF working-group charter Q1 2027; v1.0 specification Q1 2028, with reference adapters donated by the AumOS implementation and a community seed-corpus call for contributions. The standard ships with the cross-tool consistency harness (Paper 17, §6) as the conformance gate.
