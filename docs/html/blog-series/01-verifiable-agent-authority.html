Thesis

Agent systems fail open on authority: platforms mint coarse bearer tokens, MCP tools inherit ambient privilege, and multi-agent hops launder intent. AumOS treats authority as a verifiable substrate—not a dashboard. This essay walks the composition of SPIFFE identity, OAuth RAR-structured scopes, DPoP-bound credentials, Cedar/OPA decision equivalence, and the AumOS envelopes P1 AAE, P7 ABS, and P12 CAP.

1. The authority gap in production agents

Every relying party that honors an agent request faces the same incomplete evidence package: a platform credential that says “this SaaS may call me,” not “this human delegated this agent, for this audience, for this budget, on this attested host, until this expiry, with this revocation channel.” SPIFFE solved workload identity for services[1]; agents add dynamic human delegation, tool graphs, and multi-hop OBO (on-behalf-of) paths that classical mTLS never modeled.

OAuth’s answer is partial. Rich Authorization Requests (RAR) give structured authorization_details[3]; DPoP binds tokens to keys[4]; Token Exchange scopes downstream hops[5]. AWS’s three-layer Cedar model for multi-agent chains shows how policy can check capability, delegation path, and originating user together[6]. None of these alone is an agent authority envelope. AumOS’s claim is that they must be composed into a single verifiable artifact with a fail-closed verification contract.

2. The composition stack (not a fork)

AumOS doctrine is explicit: do not reinvent SPIFFE, OAuth, or Cedar. Profile them. I1 agent-identity and I2 identity-bindings attach SPIRE attestation plugins so agent pods get short-lived SVIDs. T1 trust-core verifies signatures with a single Rust authoritative implementation—no dual security invariants. T2 authority-spec holds the normative AAE schema (CDDL/JSON) that every language package must pass before release.

Policy compilation (R5) turns regulatory/NL intent into OpenShell + OPA/Cedar rules; R6 policy-bridge runs decision-equivalence tests so engines cannot disagree silently. Credential brokering (R4) issues agent-scoped secrets under DPoP-style sender constraint—stolen tokens without the proof-of-possession key are inert.

AumOS-native composition (not an IETF standard)

P1 AAE, P7 ABS, and P12 CAP are AumOS protocol profiles. There is no single public “Agent Authority Envelope RFC.” The normative external pieces are SPIFFE, RAR, DPoP, Token Exchange, Cedar/OPA, and SSF/CAEP. AumOS composes them into one verification contract and ships CDDL under specs/protocols/.

3. Agent Authority Envelope mechanics

Verification is an intersection, not a union: principal-granted capabilities ∩ host-attested capabilities ∩ protocol-declared tool schemas. If any set is empty after intersection, deny. ABS budgets throttle cumulative tool calls, dollar spend, and data egress—counters must be atomic under concurrent tool storms. CAP binds the envelope to sandbox/TEE measurements so a token minted for a confidential GPU cannot be replayed on an unattested laptop.

Normative crypto for v1: prefer COSE (RFC 9052) for compact CBOR envelopes verified in T1; JWS remains an interoperability mapping, not a second authoritative implementation. Dual crypto without a single verifier path is how signature-check bugs fork silently.

Fail-closed default

Missing revocation check, clock skew beyond skew budget, audience mismatch, or CAP miss → hard deny. Soft-fail “best effort authz” is how agent breaches become production incidents.

US model-risk posture (banking)

For US regulated deployers, OCC Bulletin 2026-13 / Fed SR 26-2 revise model-risk guidance and explicitly defer generative/agentic AI from that booklet’s scope—while safety-and-soundness and third-party risk duties remain. Authority envelopes are how you produce evidence those duties still demand.

5. AumOS component mapping

Wave-1 ships T1 and mocked identity; Wave-2 activates real I1 SPIRE integration. Protocol specs for P1/P7/P12 live under specs/protocols/ with CDDL and conformance vectors. Cross-language packages do not release a protocol version until the conformance suite is green—invariant I-style discipline from the stack pressure test.

6. Implications for implementers

If you only adopt MCP without authority-aware admission, you standardized tool plugs into an ungoverned wall socket. Start with SPIFFE for the agent runtime, RAR-shaped scopes for tools, DPoP for vault egress, and a signed envelope your gateway verifies before any tool dispatch. AumOS is the reference composition—not a competing identity product.
