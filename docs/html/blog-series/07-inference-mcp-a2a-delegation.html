Thesis

MCP standardizes tools; A2A standardizes agent-to-agent messaging. Confusing them produces insecure gateways. AumOS X8 is authority-aware MCP admission; P10 MADE profiles multi-agent delegation; N1–N3 are the inference edge.

1. MCP vs A2A split

MCP is USB-C for tools/resources/prompts[1,2]. A2A is agent interoperability over HTTP/JSON with a formal spec and LF momentum[3,4]. Official topic pages explain coexistence[5]; Auth0 covers security framing[6]. AumOS keeps both: tools go through X8; agent peers use MADE + AAE.

2. Authority-aware MCP gateway

X8 admission algorithm (fail-closed):

  1. Resolve skill package → verify P5 SSP signature (T1).
  2. Load AAE → check aud, exp, revocation, tool allow class.
  3. Intersect CAP: runtime measurement matches envelope bind.
  4. Debit ABS budget for tool class; deny on exhaust.
  5. Dispatch tool; emit AAR (Essay 5) for allow and deny.

Unsigned community MCP servers are untrusted code—because they are. P5 is AumOS packaging, not a claim that MCP itself ships skill signatures.

3. MADE delegation exchange

AumOS-native (P10 MADE)

Multi-Agent Delegation Exchange is an AumOS profile for constrained inter-agent authority. It sits on A2A messaging and OAuth token exchange—it is not the A2A specification itself.

Sequence sketch: Agent A holds AAEA. A creates MADE with parent_jti, task hash, residual RAR details (strict subset), TTL, and signature. Agent B accepts only if residual ⊆ A’s grants and OBO token exchange succeeds. B’s tools at X8 use AAEB derived from MADE—not A’s full envelope. Confused-deputy fix: B cannot widen scope by asking A2A peers for “help with everything.”

4. Inference stack

N1 OpenServeKit targets an OpenAI-compatible wire surface for backend-agnostic serving (ecosystem pattern; not “the OpenAI product”). N2 BridgeRT abstracts vLLM/TRT-LLM[7,8]; N3 InferenceProxy adds auth, rate limits, prompt filters, semantic cache; N4 TenantGuard owns MIG multi-tenancy. Authority checks belong in N3/X8—not only inside the model server process.

5. Implications

Ship MCP for productivity, A2A for federation, and AumOS authority for both—or accept that interoperability multiplies blast radius. Prompt injection that fires tools is not a model-only bug; it is an admission-control bug at X8. Multi-agent OBO without residual scope is privilege laundering with better branding.

US / India note

Tool logs and delegated actions often process personal or customer data. DPDP and US third-party / safety-and-soundness expectations both require knowing which agent acted under which residual authority—MADE + AAR, not chat screenshots.
