Part 1 · Implementation Gap Analysis
Framing — read this first

The repo's own docs/final-verification-report.md claims "691 tests passing, feature-complete at v1.0.0". The brutally honest code-level audit (see critical-analysis.html) found that most "implementations" are documented stubs the report itself defers to "task 03". The 7 cryptographic-spine findings (C1–C7) are claimed-but-not-delivered security invariants. AumOS is best understood today as a comprehensive architectural specification with reference-shape implementations — not deployable v1.0 software. This catalog is the roadmap to close that gap.

1C.Missing cross-cutting infrastructure

These are not "missing components" — they are infrastructure every production system needs that no AumOS component provides today. The 49 components implement domain logic; nothing implements the platform substrate they run on. Each gap below is currently served by a stub, a hardcoded URL, or nothing at all.

GAP 1
Service mesh / mTLS
No service-to-service TLS anywhere. I1 agent-identity serves plain HTTP (H6). The "mTLS + SPIFFE SVIDs (I1) + certificate transparency" threat-model promise in 02-architecture.md §9 is not delivered. Fix: ship Istio/Linkerd sidecars or a SPIRE-issued mTLS mesh; make https:// + client-cert the only accepted transport.
GAP 2
Service discovery
No registry. Components find each other via hardcoded URLs / env vars. No Consul, no Kubernetes DNS-based discovery contract, no health-aware load balancing. Fix: a typed discovery surface (K8s Service + headless, or a SPIRE-anchored registry) so R3 can find R4, E1 can find I1, etc.
GAP 3
Distributed tracing
No W3C Trace Context propagation. E1 emits JSON; Trace IDs are invalid W3C (derived from UUID string-slicing) per H9. No real OTLP export. Fix: adopt OpenTelemetry SDKs across all 4 languages; emit OTLP to a collector; propagate traceparent through every AAE/AAR.
GAP 4
Circuit breakers
No retry, backoff, or circuit-breaker patterns in any component. A slow downstream (e.g. R4 credential-vault) blocks every caller; no bulkhead. Fix: introduce a shared resilience crate (e.g. tower in Rust, failsafe-go in Go) with bounded retries, jittered backoff, and per-dependency breakers.
GAP 5
Unified config management
No unified config system. Each component reads its own env vars; no schema, no validation, no layered config (file → env → flag). Fix: a typed config layer (e.g. figment/config-rs, viper in Go) with a shared AumOSConfig schema and fail-closed validation on startup.
GAP 6
Health aggregation
Each component has a /healthz but there is no aggregate health dashboard, no readiness vs liveness distinction, no dependency graph. Fix: an aggregate health surface (X7 console or a dedicated operator) that rolls up dependency health into a single trust-posture indicator.
GAP 7
Secret rotation
R4 credential-vault issues scoped credentials but does not rotate signing keys. Root keys are static for the lifetime of the deployment. Fix: automated rotation schedule for root CA, AAR signing keys, and SBOM signing keys; key ceremony procedure (see 3C).
GAP 8
Multi-region
No cross-region replication story for the attestation ledger. A single-region S2 provena-chain is a single point of regulatory failure. Fix: geo-replicated ledger (TimescaleDB multi-node or a Rekor-style gossip transparency log) with documented RPO/RTO.
GAP 9
Observability dashboards
No Grafana dashboards, no Prometheus metrics, no alerting rules. The /metrics endpoint does not exist (H9). Fix: ship a reference Grafana stack + Prometheus scrape config + JSON dashboards per plane (12 dashboards for the 12 planes).
GAP 10
Database / persistence layer
provena-chain is in-memory only (H10) — a tamper-evident ledger in RAM is not tamper-evident across restarts. No database backend anywhere. Fix: PostgreSQL/TimescaleDB persistence (see 3A) for the ledger, AAR store, and revocation list.

1D.Protocol completeness gaps

The 12 open protocols (P1–P12) are the contract plane — the spine of the whole system. They are also the least-complete part of the implementation. The audit found four distinct gaps.

GapCurrent stateWhat's missingSeverity
Normative schemas Only P1 (AAE) has CDDL + JSON-Schema (P1-aae.cddl, P1-aae.schema.json) P2–P12 each have only a markdown sketch. Every protocol spec file claims "normative schema lives at … CDDL" but the file does not exist for 11 of 12. HIGH (H4)
Cross-language conformance vectors Only 1 conformance vector exists: sign-ed25519-conformance-001 over the literal bytes "hello aumos conformance" The bytes are verified raw — NOT on canonical_cbor(payload). testvectors/README.md promises C1-1/C1-2/R2/R3/R4/I1/P1/P2 vectors; none exist. HIGH (H3)
Adversarial test vectors None exist for any protocol The P2 spec explicitly requires 6 classes of adversarial vectors (confused-deputy, replay, truncation, forgery, canonical-ambiguity, nonce-reuse). Zero are shipped. HIGH
Protocol-level conformance suite Only T1's Ed25519 is tested cross-language No "produce a P1 here, verify it in Rust/Python/Go/TypeScript" round-trip suite for P2–P12. The contract plane is not actually machine-checked end-to-end. HIGH
Why this matters

The whole architectural thesis (02-architecture.md §6) is that "the contract plane is the real platform spine … breaking changes here break every implementation." But if only 1 of 12 protocols has a normative schema and only 1 conformance vector exists, the spine is not load-bearing. Closing 1D is the highest-leverage documentation task in the project.

Part 3 · What MUST We Add Beyond the 49 Components & 12 Protocols

Components implement domain logic; protocols define the contract. Neither is a runnable platform. Part 3 catalogs the substrate AumOS depends on but does not own — the infrastructure services, the developer tooling, the enterprise capabilities, and the ecosystem integrations that MUST exist for a real deployment. These are not optional polish; they are the difference between a specification and a product.

3A.Essential infrastructure services

Ten services the system cannot run without. AumOS adopts these rather than reinventing them (per 02-architecture.md §7). Each maps to at least one open High/Medium finding.

INFRA-01

SPIRE server cluster

The identity root for all components. I1 agent-identity ships an in-process Ed25519 CA in v1.0 (final-verification-report task 03). A production deployment MUST front I1 with a SPIRE cluster that mints real SPIFFE SVIDs. Resolves H6 (plain HTTP) and the SVID lifecycle.

INFRA-02

OpenTelemetry Collector

The observability backbone. E1 emits JSON today (H9); OTLP export is deferred. A collector fan-outs traces (Tempo/Jaeger), metrics (Prometheus), and logs (Loki) from one pipe. Resolves H9.

INFRA-03

Kafka cluster

The async event bus for CloudEvents. X9 incident-exchange (P9 AIX) and X2 NOOA audit-streamer are pub/sub by design but have no broker today. Kafka (or Redpanda) is the documented target.

INFRA-04

Sigstore Rekor

The transparency log for anchoring. S2 provena-chain checkpoints are signed in v1.0 but not anchored to a public Rekor instance. Real Rekor integration is task 03 for S2/T1.

INFRA-05

PostgreSQL / TimescaleDB

Persistence for the provena-chain ledger. The ledger is in-memory today (H10) — a tamper-evident ledger in RAM is not tamper-evident across restarts. TimescaleDB gives time-series queries for the audit timeline.

INFRA-06

Redis

Semantic-cache backend for N3 inference-proxy. The proxy's cache interface is shipped; the backend is a stub. Redis (or Redis-compatible Dragonfly) makes the cache real and bounds latency.

INFRA-07

OPA cluster

The policy evaluation engine for R3/R5. R3 kill-switch and R5 policy-compiler use a MockPolicyEngine in v1.0 (task 03). A real OPA (or Cedar) cluster makes Rego/Cedar decisions enforceable.

INFRA-08

Grafana + Prometheus

The monitoring stack. No dashboards exist (1C GAP 9). Ship 12 reference Grafana dashboards (one per plane) + Prometheus scrape config + alerting rules.

INFRA-09

HashiCorp Vault

The secrets backend for R4 credential-vault. R4 has the trait + stubs (task 03). Vault (or AWS Secrets Manager / K8s Secrets) makes issuance and rotation real. Resolves H11 (no-op revoke_all).

INFRA-10

NVIDIA GPU operator

The Kubernetes GPU management layer. N4 tenant-guard and F4 fleet-marshal's MIG/MPS partitioning depend on the NVIDIA GPU operator being installed on the cluster.

Enterprise identity federation. Today the only identity is the SPIFFE workload identity (I1). Human-facing consoles (X7) and CI runners need SAML/OIDC federation to Okta, Entra ID, Ping.

ENT-02

RBAC engine

Fine-grained role-based access beyond the governance ladder (EN-17). Resource-level permissions: who can issue an AAE, who can revoke, who can read the ledger.

ENT-03

Multi-cluster management

Fleet of AumOS deployments across regions. A control-plane that federates attestation roots, syncs policy bundles, and rolls up audit across clusters.

ENT-04

Data residency enforcement engine

Automatic data routing by classification (EN-10/EN-12). A policy engine that refuses to route L3+ data across residency boundaries and emits a violation event on attempt.

ENT-05

SLA monitoring

Uptime, latency, and compliance SLAs with alerting. SLOs per plane (12 planes → 12 SLOs) wired into the Grafana stack (INFRA-08).

ENT-06

Backup & disaster recovery

Automated backup of ledgers, keys, configs. Documented RPO/RTO per topology. Resolves the multi-region gap (1C GAP 8).

ENT-07

Key ceremony procedures

Documented HSM key generation and rotation ceremonies (M-of-N quorum, witnesses, attested ceremony VM). Required for FedRAMP and for sovereign (X10) deployments.

ENT-08

Penetration testing framework

Annual third-party pentest with findings integrated into the audit backlog. Repeatable adversarial harness that re-runs the P2 6-class vectors (1D) every release.

Bottom Line

The path from specification to platform

The 49 components and 12 protocols are a comprehensive architectural specification with reference-shape implementations — not deployable v1.0 software. The critical-path work to close that gap is bounded, sequenced, and already begun.

Sequenced critical path

  1. Close the cryptographic spine — C1–C7 fixed in b8afc89; land the cross-language canonical-CBOR conformance vectors (H3) so the fix cannot regress.
  2. Close protocol completeness (1D) — CDDL + JSON-Schema for P2–P12; the 6-class adversarial vectors for P2; the full P1–P12 round-trip conformance suite.
  3. Wire the infrastructure substrate (3A) — SPIRE, OTel collector, PostgreSQL for provena-chain (H10), Vault for R4 (H11), OPA for R3/R5. Each resolves a documented High finding.
  4. Stand up transport security — mTLS mesh (H6), W3C tracing (H9), circuit breakers, aggregate health. The platform substrate must be trustworthy before domain logic is.
  5. Ship the developer tooling (3B) — aumos init/dev/test/deploy, Docker Compose dev env, Helm registry. This is what turns the catalog into the 5-minute quickstart (DX-27).
  6. Add the enterprise + ecosystem layer (3C/3D) — SSO, RBAC, multi-cluster, data residency, the 8 ecosystem adapters. This is what unblocks procurement.
The honest summary

AumOS today is the most thoroughly specified open secure-AI stack in the market: 49 components reconciled across 4 source portfolios, 12 protocols, 10 compliance frameworks, 12 formal invariants, 691 tests. The gap to "deployable v1.0 software" is real (28 audit findings, 10 infrastructure services, 34 must-add items) but it is bounded, sequenced, and mostly documentation-and-integration work rather than novel research. Closing it is a matter of months, not years.
