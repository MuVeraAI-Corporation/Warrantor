# Implementation and dependency evidence map

Status: repository-specific operational audit plus normative and reproduced operational-trust review  
Snapshot: 2026-09-01  
Scope: dependency reproducibility, vulnerability management, build provenance, release controls, workload identity, sandboxing, observability, and disclosure operations

This file connects external evidence to the implementation that actually exists in the repository. It is not a complete security audit and does not change production code. Counts are filesystem observations from the current checkout and include experimental or legacy packages when they still participate in repository workflows.

## Prioritized operational actions

### P0 — claims and supply-chain trust

1. Quarantine the Rekor v1.3.6 and SPIRE deployment paths from supported profiles; keep mTLS disabled and remove “working Rekor v2” and “live/unrevoked SVID” claims until acceptance gates pass.
2. Correct every SLSA Level 3 statement to Level 2 now. Track Level 3 as an evidence-gated target, not a property of the provenance file format.
3. Pin every third-party GitHub Action to a reviewed full commit SHA and retain a nearby release-version comment; use automated update proposals to preserve maintainability.
4. Add a consumer-side release test that rejects an artifact unless digest, repository, source revision, signer, builder and allowed workflow match policy.
5. Establish deterministic Python resolution for all shipped packages, preferably one governed workspace lock with exportable per-artifact inputs; do not treat lower bounds such as `cryptography>=42` as release reproducibility.
6. Materialize `go.sum` for every module that resolves external packages and add `govulncheck`; document genuinely dependency-free modules rather than assuming missing sums are defects.
7. Freeze Warrantor's envelope decision on DSSE/in-toto, publish the authority/action/evaluation predicate URIs and implement exact-byte, keyid-confusion, deletion, replay and expected-set reconciliation vectors before new receipt code diverges.
8. Specify and implement W6 quota enforcement as one linearizable, durable and idempotent authorize-and-consume operation. Add SAGA's quota-one/two-request race and policy-order permutation as release-blocking counterexamples before describing any residual-action or revocation SLA.
9. Freeze the twelve invariant statements and formal-assurance evidence ladder. Add SentinelAgent's six reproduced authority/evidence defects as release-blocking vectors; invoke model checkers directly; preserve full result and state counts; and require a model-action-to-production-event mapping before using “machine checked” in external claims.
10. Add Open Agent Auth's garbage delegation signature, missing binding store, absent WPT target/replay, raw MCP bypass, mutable/deletable audit and 13 live-integration failures to the conformance corpus. Do not copy the beta implementation or claim compatibility until current-draft fixtures pass against an independent implementation and every applicable live gate is green.
11. Adopt AuthZEN 1.0 as the external PDP/PEP contract. The two-independent-PDP/two-gateway adoption gate was attempted and failed: final-wire mismatch, incomplete primitive coverage, post-decision mutation and uncorrelated approval were reproduced. Do not ship either reviewed gateway path unchanged.
12. Implement the Warrantor reference PEP and common COAZ/MCP corpus now: final field validation and discovery, explicit Cerbos/OpenFGA semantic profiles, three current-core false-denial cases, notification extensions, post-decision mutation, mapping swap, approval replay, retry/replay, raw transport, nested call, result/effect substitution and crash reconciliation. Release only after two independent PDP targets and two independently maintained PEPs pass the pinned corpus.
13. Build the invariant corpus as an independent authority-to-effect profile, not an ASB or AgentDojo fork. Repair/reimplement selected cases, preserve public benchmark adapters, add private defense-adaptive holdouts, and make mutation score, semantic utility, repeated-attempt risk, cross-engine/cross-implementation transfer and signed evidence release gates.
14. Retire the universal attack-to-policy novelty claim and quarantine the experimental candidate/approval fragments from production. Reject wildcard generated scope and unkeyed hashes labeled as signatures. Freeze typed finding/candidate/target-compilation/approval/deployment-effect/regression records, then prove one deterministic monitor→canary→enforce→rollback/evidence-renewed-expiry path across two PDP targets and one F5/Datadog/Defender/SOAR adapter. Execute the fifty negative vectors in `artifact-review-commercial-attack-to-policy-prior-art.md`, preserve independent effect evidence and commission patent counsel before external novelty/FTO claims.
15. Quarantine X9 `to_ocsf()` and remove every OCSF-conformance statement until replacement. Pin and compile OCSF 1.9 in CI; emit Incident Finding class 2005 with valid lifecycle and required fields; validate unknown-field, wrong-class, activity, metadata, identity, delegation and record-integrity negatives; add AICIE/OECD, STIX and CSAF loss-declared projections; and require two independent producers/consumers to pass the 76 vectors in `artifact-review-safe-aix-incident-exchange.md` before interoperability claims.
16. Quarantine present-tense W5 network-enforcement and R7/S6 eBPF/Falco/Tetragon claims. Define the signed monotonic capability catalog, configured issuer trust, one-shot exact-operation permit and W2 result/effect predicates; build the first OpenShell-backed E6 vertical slice; execute every vector in `artifact-review-default-deny-egress.md`; then add Cloudflare or Kubernetes/Cilium as a differential target and obtain independent E7 review.

### P1 — continuous vulnerability and evidence coverage

1. Add OSV-Scanner V2 across repository locks, manifests, built images and emitted SBOMs; preserve raw SARIF or JSON evidence. Complement it with ecosystem-aware checks where they add reachability or policy value.
2. Add RustSec/cargo-audit or cargo-deny over the committed Rust lock and a dependency policy for advisories, licenses, sources and duplicate versions.
3. Expand Dependabot or an equivalent updater to every governed npm, Go and Python resolution root. A single Python directory is not representative of 54 projects.
4. Generate an SBOM for every release artifact and platform package, attach or attest it, and prove that empty, stale and unrelated SBOMs fail verification.
5. Run OpenSSF Scorecard as a measurement input and remediate individual high-risk findings. Do not optimize for the aggregate number or present it as an audit opinion.

### P2 — runtime assurance and operations

1. Adopt OpenTelemetry GenAI conventions for interoperable traces while making signed receipt identifiers the evidence spine. Record sampling, redaction, privacy, retention and trust boundaries.
2. Build workload identity on a pinned upstream SPIRE/controller-manager or managed SPIFFE profile; implement the actual native or Envoy mTLS data plane, separately authorize agent actions, preserve initiating-principal context and record credential-validation evidence rather than only a SPIFFE ID.
3. Treat Wasmtime upgrades as security releases, exercise sandbox-escape response, and benchmark enforcement overhead with the exact host functions and resource limits Warrantor exposes.
4. Run a coordinated-disclosure tabletop and a release-key/build compromise exercise; record acknowledgement time, containment, revocation, rebuild, customer notification and recovery evidence.
5. Define service-level indicators for notary availability, receipt durability, policy propagation, kill-switch latency, revocation residual actions and verifier success before publishing operational SLAs.

## Evidence limits

- This audit inspected repository configuration and primary documentation but did not execute CI, query private repository settings, generate release attestations, run vulnerability scanners, or validate a published artifact.
- Missing lock or checksum files do not prove that a module has external dependencies; they identify a reproducibility question that must be resolved per module.
- The 19 mutable action references are distinct references, not necessarily 19 unique upstream codebases or 19 exploitable vulnerabilities.
- Security controls in repository files are design evidence. Their effective operation requires run history, branch/ruleset configuration, generated artifacts, verifier output and incident exercises.
- Docker, Kubernetes and Helm were unavailable for this wave. The SPIRE server rejection was reproduced with the official pinned binary; remaining topology findings are static contract evidence and require a corrected clean-cluster follow-up.
