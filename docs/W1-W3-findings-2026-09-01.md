# W1–W3 findings — the win and the regression are the same defect

**2026-09-01. No GPU, no spend.** Statistics over result documents already on disk,
after R1 confirmed the baselines reproduce.

---

## The headline

**Every fine-tune in this programme damaged its severity field, and the damage is
invisible to a recall-only review.** Four of four: two halved the `controversial`
class, one destroyed it entirely, one flooded it with junk vocabulary. The damage
moves in both directions — when it collapses one way recall rises and looks like
the programme's best result; when it destabilises the other way recall falls
eleven points. Same failure, and only one of the two directions gets investigated.

This is not a 0.6B problem. The 4B adapters lost **56%** and **65%** of their
`controversial` verdicts while scoring *within noise* on recall — they would have
passed any review that looked only at the headline metric.

## W1 (FINAL) — the gain is real, and so is the loss

> **This section's original conclusion was wrong, and it is corrected below rather
> than rewritten.** I first called this adapter a clear winner, then called the win
> "very likely an artefact" of severity relabelling. The paired test against the
> **correct 0.6B baseline** — which did not exist on disk when I wrote that —
> supports neither.

**The recall improvement is genuine and statistically significant.**

| | |
|---|---|
| candidate-only catches | **115** |
| baseline-only catches | 31 |
| exact two-sided *p* | **< 0.0001** |
| recall | 0.7150 → **0.7818** |
| false-positive rate | 0.0854 → **0.0550** (improved) |

115 items newly caught against 31 lost is not relabelling. My "consistent with
relabelling" claim compared against the **4B's** 266 controversial verdicts; the
0.6B base emits **122**, and the arithmetic does not carry over.

**And the class is still gone.** Baseline 122 `controversial`, candidate **0**.

### Where the 122 went, exactly

| Baseline said `controversial` | Candidate says |
|---|---|
| 81 | `unsafe` |
| 41 | `safe` |

Of those 122, **76 are true positives**. The baseline caught all 76 — under
`controversial_is_harmful=True` a controversial verdict already counts as harmful.
The candidate catches **65**. So inside the former controversial set it *loses 11
true positives*, while gaining 115 elsewhere.

### So the honest disposition is a decision, not a verdict

This is **a better binary classifier that can no longer make a three-way
distinction**. Both headline metrics improve. What disappears is the ability to
express `controversial` at all — which means:

- **The `Controversial=SAFE` policy knob becomes a silent no-op.** Anyone who sets
  it gets no behaviour change and no warning. That is the same class of defect as a
  bound that reads enforced and is observed.
- **The 11 lost true positives are exactly the ones the three-way distinction was
  protecting** — items ambiguous enough that the base model declined to call them
  outright unsafe, and which a `controversial → harmful` policy then caught.
- It is not a drop-in replacement for the model every published figure describes,
  even though it scores better than that model on both metrics.

**Recommendation: do not auto-promote; put it to a human decision** with the
severity loss stated. A gate that promoted on recall and FPR alone would ship it,
and a gate that rejected on class loss alone would discard a real +115. Neither is
right on its own, which is why `paired_analysis` returns `VOID` — *the comparison
is not automatable*, not *the candidate is bad*.

## W1 (original, superseded) — the winner is very likely an artefact

`warrantor-guard-0.6b-expguard-weak-exp06` cleared every stated promotion bar:
982 caught against 942 required, 56 false positives against a 116 ceiling,
+0.0668 against a 0.0353 minimum detectable delta, and both untrained floors rose.

**Then the severity distribution:**

| Run | safe | unsafe | **controversial** |
|---|---|---|---|
| Base 4B, ExpGuardTest | 1286 | 723 | **266** |
| **Candidate** | 1237 | 1038 | **0** |

**The third severity class is completely extinguished.**

This is the failure the recipe named in advance and left unmeasured:

> *"MEASURE THE 0.6B's SEVERITY EXPOSURE BEFORE TRAINING, and budget for it as the
> most likely failure mode… On ExpGuardTest the 4B's `Controversial` verdicts carry
> 235 of 954 true positives — losing them drops recall 0.7596 → 0.5725… The 0.6B's
> exposure is recorded NOWHERE."*

The arithmetic is consistent with relabelling rather than improvement. Base
harmful predictions = 723 unsafe + 266 controversial = **989**. Candidate = 1038
unsafe + 0 controversial = **1038**. Under `controversial_is_harmful=True` both
counted as harmful all along, so the model has largely converted one harmful label
into another and added 49.

**Disposition: do not promote.** A model that has lost an entire severity class is
not the same instrument as the one every published figure describes, whatever the
aggregate says. This is exactly the case the gate's per-class floors exist for —
and the floors passed, because floors measure *categories*, not *severity*.

### What is still unresolved, honestly

- **The 266 above is the 4B's count, not the 0.6B's.** The candidate is a 0.6B, so
  the correct comparison is against a 0.6B ExpGuard baseline — which is being
  measured now. On WildGuard the 0.6B base emits **48** controversial against the
  4B's 68, so the 0.6B carries less severity mass to begin with and the ExpGuard
  figure may be smaller too. **The direction of this finding is not in doubt — a
  candidate emitting zero is still a lost class — but the magnitude is pending.**
- **No McNemar was possible** for this adapter at the time of writing, for the same
  reason. It is queued the moment the baseline lands.
- So +0.0668 remains a delta against a *pinned rate*, not a paired result.
- Closing this needs one baseline run: the 0.6B base on ExpGuardTest. Local, free,
  a few hours.

## W2 — the eleven-point regression, solved

`warrantor-guard-0.6b-weak-category-local` fell 0.8488 → 0.7374. **Cause found.**

| Run | safe | unsafe | controversial | **invalid** |
|---|---|---|---|---|
| Base 4B, WildGuardTest | 1000 | 631 | 68 | — |
| **Regressed candidate** | 1070 | **386** | **231** | **`others`: 11, `unethical acts`: 1** |

Two things happened at once, and both are severity-field damage:

1. **Category names leaked into the severity slot.** `others` and
   `unethical acts` are *category* vocabulary appearing where a severity value
   belongs — 12 samples. The recipe notes predicted this exactly: *"the field came
   unmoored and filled with its neighbour's vocabulary — the 0.6B began emitting
   category names ('violent', 'others') into the severity slot."*
2. **Mass shifted from `unsafe` to `controversial`**: 631 → 386 while
   controversial rose 68 → 231. Harmful predictions fell from 699 to 617.

**McNemar, paired on positives:** baseline caught 105 the candidate missed;
candidate caught 15 the baseline missed. **χ² = 66.01, p < 0.0001.** This is not
noise. It is the largest single regression in the programme.

## W3 (revised) — every fine-tune damaged its severity field

**Superseding the table below.** The first pass paired the 0.6B adapters against
the **4B** base because no 0.6B baseline existed on disk. That baseline has now
been measured, and re-running with correct size-matched pairs changes the finding
from *one adapter flattened severity* to **every adapter damaged it**.

| Adapter | base-only | cand-only | exact *p* | `controversial` | Verdict |
|---|---|---|---|---|---|
| `0.6b-adversarial` | 23 | 16 | 0.3368 | **48 → 0** | **VOID — class lost** |
| `0.6b-weak-category` | 91 | 9 | <1e-9 | 48 → 231 **+ junk** | baseline better |
| `4b-adversarial` | 4 | 7 | 0.5488 | 68 → 30 (−56%) | within noise |
| `4b-weak-category` | 8 | 6 | 0.7905 | 68 → 24 (−65%) | within noise |

**Not one of the four preserved it.** Two halved the class, one destroyed it, one
flooded it with junk vocabulary.

`0.6b-adversarial` is the case that matters most for the gate. On recall it is
*p* = 0.3368 — unremarkable, and it would have passed a recall-only review — while
having lost the `controversial` class entirely. A recall comparison between models
with different output vocabularies is not meaningful whatever the arithmetic says,
which is why `paired_analysis` returns **VOID** rather than *within noise*.

**A number also got more honest.** `0.6b-weak-category` was 105-vs-15 against the
4B base; against its own 0.6B base it is **91-vs-9**. Same conclusion, correct
counts.

### Method note

Exact binomial rather than chi-square: one comparison here has **11 discordant
pairs in total**, where the approximation is not trustworthy. Validated against a
result this project already holds — 2-vs-4 returns 0.688, the figure recorded for
that historical case.

## T1 arm A — the damage is deterministic, not stochastic

**2026-09-01, Modal A100.** The control arm retrains the W1 configuration exactly: the recipe
with the target-modules override **unset**, so all seven modules, rank 16, alpha 32, 11,272 rows,
bf16. Scored on ExpGuardTest at the baseline's own settings (`num_ctx` 8192, seed 0, greedy).

It reproduces the W1 result to within one item.

| | base-only | cand-only | exact *p* | `controversial` | `unsafe` |
|---|---|---|---|---|---|
| `exp06` (22 Aug, local) | 31 | 115 | <0.0001 | 122 → **0** | 1038 |
| **T1-A control** (1 Sep, A100) | 31 | 116 | <0.0001 | 122 → **0** | 1038 |

Two independent training runs, ten days apart, on different hardware, produce the **same**
`unsafe` count and an identical `baseline-only` count. The `safe` counts differ by exactly 7 —
which is exactly the number of samples whose backend call failed in the second run
(1237 = 1230 + 7). Outside those 7 transient Ollama errors, the two runs agree item for item.

**So the severity collapse is a property of the configuration, not of the run.** It is not
noise, not a seed, not an unlucky checkpoint. The same recipe extinguishes the same class every
time. That is what makes the mechanism testable at all: arms B and C can now attribute it,
because there is no run-to-run variance to hide behind.

One caution on the reported figure. T1-A's headline recall reads 0.7842 against `exp06`'s 0.7818,
and **that difference is an artefact of the 7 backend errors, not an improvement** — the harness
runs `fail_mode=closed`, so an errored sample is scored as harmful. The paired counts above
exclude errored items and are unaffected. A point estimate flattered by a dead backend is exactly
the reading the paired test exists to refuse.

**Arms B and C dispatched** on this result (attention-only, MLP-only), which is the gate that was
set in advance: had the control not reproduced the damage, the diagnosis would have been wrong
and both were to be cancelled.

## T1 — the module hypothesis is REFUTED

**2026-09-01, three arms on Modal A100.** T1 asked where the severity field lives. The
training-plan-v2 diagnosis was that `supervise_severity` damages severity because the adapter
touches whatever weights carry it, and that the fix is therefore to **retarget the adapter** — to
choose target modules that do not carry the severity head. T1 tested that directly.

| arm | modules | recall | FPR | safe | unsafe | **controversial** | base-only | cand-only | exact *p* |
|---|---|---|---|---|---|---|---|---|---|
| baseline | — | 0.7150 | 0.0854 | 1290 | 863 | **122** | — | — | — |
| **A** control | all seven | 0.7842 | 0.0589 | 1230 | 1038 | **0** | 31 | 116 | <0.0001 |
| **B** attention | q,k,v,o | 0.8439 | 0.1649 | 1047 | 1227 | **0** | 2 | 164 | <0.0001 |
| **C** MLP | gate,up,down | 0.7930 | 0.0864 | 1191 | 1084 | **0** | 19 | 117 | <0.0001 |

**All three go to zero.** Attention-only destroys the class. MLP-only destroys the class. The two
module families are disjoint and each is independently sufficient to extinguish it.

**So severity does not live in a module family, and retargeting the adapter cannot save it.** The
proposed fix is dead, and it is dead on evidence rather than on argument. Whatever destroys the
class is carried by the training objective or the labels, not by the weight subset the adapter
happens to touch — the one factor T1 varied is the one factor that made no difference to the
outcome.

### The modules do matter — for calibration, not for severity

The arms are not interchangeable, which is what makes the null result credible rather than a
failed manipulation:

- **Attention-only is badly miscalibrated.** FPR nearly doubles against the baseline, 0.0854 →
  **0.1649**, and the model calls 1227 of 2275 items unsafe. Its recall of 0.8439 is the
  programme's highest and is substantially bought with false positives.
- **MLP-only is FPR-neutral** (0.0864 vs 0.0854) while gaining recall.
- **All seven improves FPR** to 0.0589.

Restricting the adapter therefore changes behaviour a great deal. It simply does not change
*this* behaviour. A manipulation that moved nothing would be uninformative; this one moved
calibration by a factor of nearly three and still left the severity class at zero.

### What is left

Two hypotheses survive, and T1 did not test either:

1. **The objective.** `supervise_severity` trains one output field, and the recipe notes already
   concluded a real fix needs *separate parameters* — a second adapter carrying severity alone.
2. **The labels.** If the training corpus itself under-represents or never emits `controversial`,
   no choice of target modules can preserve what the data does not teach. **This is the cheaper
   of the two to check and should come first** — it is a corpus query, not a training run.

## What this means for the training plan

1. **No adapter in the programme is currently promotable.** The one that cleared
   its bar did so with a flattened severity field; the rest are noise or worse.
2. **Severity stability must become a gate criterion.** The per-class floors did
   not catch this because they measure categories. A severity-distribution check
   would have caught both W1 and W2 immediately, and it costs nothing.
3. **Two baseline runs are the cheapest useful work left**: the 0.6B on
   WildGuardTest and on ExpGuardTest, to make every 0.6B comparison paired and
   correctly matched. Local, free, no hypothesis required.
4. **`supervise_severity` is now refuted in both directions.** Setting it False
   destroyed recall (0.8329 → 0.6804). Leaving it True flattens the class. The
   recipe notes already concluded a real fix needs *separate parameters* — a
   second adapter, or target modules that do not carry severity. This is now
   evidenced twice over rather than argued.

---

## Publishable, and stronger than the win would have been

A fine-tune that clears every stated promotion criterion **while silently losing an
entire output class** is a better result than one that simply works. It is a
concrete instance of the paper's own thesis: aggregate metrics conceal mechanism
change, and a gate that measures only what it was told to measure will pass a model
that has quietly become a different instrument.

The programme now has that finding twice, in opposite directions, with
*p* < 0.0001 on one of them.
