## 1. Three things that need you

### 1.1 Run the installer (5 minutes)

The artifact exists and has never been executed. Executing an installer is a system-changing action
that this session's permission gate declined, correctly.

```bash
cd M:/wt-depth/desktop
ls -la dist/Warrantor-1.0.0-x64-setup.exe
sha256sum dist/Warrantor-1.0.0-x64-setup.exe
# expect: f7f6cd68517de7d01929579c6bdee5bcb938e3bd0c1cd99bd8a170d0d3b151d2
```

Then double-click it. It is per-user, into `%LOCALAPPDATA%`, and asks for no elevation by design —
an unsigned installer requesting administrator is the worst possible first prompt from a security
product. SmartScreen **will** warn, because nothing is signed yet; that is `desktop/SIGNING.md`'s
problem and it is procurement, not engineering.

What to check after launching from the install:

- the window opens and shows the console (not a white rectangle, not a dialog);
- `%LOCALAPPDATA%\...\resources\warrantor.exe` exists — the app must run **its own** agent;
- the app's own trace confirms it, if you want certainty:
  `WARRANTOR_DESKTOP_TRACE=%TEMP%\wt.log` before launching, then look for
  `agent binary: ... (bundled with the app)`.

**Already established this session, so you are only testing the installer itself:** the packaged app
contains the agent, resolves the bundled copy ahead of an empty `PATH`, starts it, opens the window
and loads the console — verified twice against `dist/win-unpacked`.

**One pipeline finding worth knowing before you cut a release on a small runner.** electron-builder
derives the `.ico` at build time with a **WebAssembly** icon tool, and on a memory-pressured Windows
box that step dies with `WebAssembly.Memory(): could not allocate memory` — *after* the app has
packaged, so it lands on the last step of a long build. Passing a pre-generated `.ico` on the CLI
gets past it:

```bash
npx electron-builder --config electron-builder.config.cjs --config.win.icon=<path-to.ico> --publish never
```

The committed config was deliberately **not** changed: the OOM is a machine being short of memory
rather than a defect, and committing a binary `.ico` would contradict `build/make-icon.mjs`'s own
stated reason for existing.

### 1.2 Accept the corpus terms and set a token (10 minutes)

`warrantor_ml.datasets` says it in its own words: *"Both primary corpora are gated behind Hugging
Face click-through terms"*, and the WildGuardMix spec records that the gate is *"auto-approved on
submit — no human reviewer — but still requires a logged-in account, an accepted form, and a read
token on the machine."* There is no token here and no Hugging Face cache at all, so the fetch fails
with HTTP 401 before any model is called. Accepting terms under an account is not something an agent
does on your behalf.

```bash
# after accepting the WildGuardMix and ExpGuardMix forms on huggingface.co
export HF_TOKEN=hf_...
python ml/benchmark_wildguard.py --num-ctx 8192 --out wildguard-2026-08-17.json
python ml/benchmark_expguard.py  --num-ctx 8192 --out expguard-2026-08-17.json
```

**Why this is now much less urgent than it was.** The reason those figures mattered is that the
shipped configuration might not have been the measured one — and it was not: this crate ran
`num_ctx: 4096` for eight releases while every published figure was measured at 8192.

That is closed twice over. `guard_parity.rs` reads `evaluate.py` as a compile-time string and asserts
every sampling knob matches (`num_ctx`, `num_predict`, `seed`, `temperature`, `top_p`, `top_k`,
`controversial_is_harmful`), so divergence is a test failure rather than a discovery. And
`warrantor guard bench --cases <file.jsonl>` measures the *running* configuration on any machine,
with Wilson intervals, reporting parity against the published figures rather than a bare number. A
worked case file is at `docs/examples/guard-bench-cases.example.jsonl`.

## 1.5 What is still open in engineering, and why each is where it is

### §3.1 — bounds are weaker than they read *(the one that matters)*

`write_paths` and `budget_cents_observed` are **Observed**, not enforced. There is no netns, no
seccomp and no firewall. The console reports `bound_strengths` honestly, but *"the agent is
bounded"* is a stronger sentence than this earns without composing with a sandbox — and it is the
product's central sentence.

This is now the largest open item by a distance, and it is the one I did **not** attempt. Emitting
a sandbox profile (bubblewrap, firejail, seccomp, a Windows AppContainer) is the obvious shape, and
I could not have verified any of it on this machine — a Linux confinement profile written and
tested nowhere is precisely the "claim rather than branch" failure §3 of this document is about.
It needs a Linux box, and it needs someone to decide which confinement mechanism this product
recommends.

### §2.4 — the agent can reach the API *(needs a decision from you, not a build)*

Same-UID: a supervised agent can read `serve/token` and call the API. The mitigation is that
`--allow-settle` is opt-in, so a stolen token yields a viewer.

The obvious hardening — **demote the session token to read-only once operators are registered**, so
write acts require a named operator token that is not on disk — reverses a decision §2.2 took
deliberately and pinned with a test
(`the_session_token_still_works_after_operators_exist`: *"otherwise starting a server would lock
out the person who started it the moment they registered anybody"*). That trade is yours, not mine,
so I left it. If you want it, the shape is a flag (`--operators-only`) rather than a behaviour
change, and it is perhaps an hour of work.

Note that act-scoped capability tokens alone do **not** close this: the agent can read an
act-scoped token off disk exactly as easily as an unscoped one. What closes it is the write path
requiring a secret that never touches this machine's filesystem.

### §3.2's remainder — email and mobile push

A webhook can front both and nothing here speaks them directly. Genuinely small, genuinely
optional, and the reason I stopped: adding an SMTP client to a crate whose seven-dependency,
tokio-free posture is a security property is a trade worth stating out loud before making.

### §1.1 — signing

A purchase, not a build. See `desktop/SIGNING.md`.

## 3. The one thing to carry forward

**The failures in this repository cluster in the claims, not the code.** Six defects this session were
statements rather than branches, and every one was invisible to a 500-test suite:

1. an error message naming a flag that did not exist;
2. a generator writing `CLAUDE.md` files asserting protections that were not in force;
3. a recall figure quoted for a configuration that was not running;
4. a warrant id that silently destroyed its predecessor;
5. a tray that never appeared in a packaged build;
6. a `--from` flag named in a refusal I had just written.

Three cheap checks now catch these classes, and all three were built *because* of the first few:

- **`tests/instructions.rs`** — every flag and command the binary names in its own output must be
  real. It caught four changes made after it existed, including one on the day it was written.
- **`tests/guard_parity.rs`** — the two implementations of the guard must agree knob for knob, read
  from each other's source.
- **Launching the packaged app** — the gap between what the packager copies and what the process
  opens has no representation in either artifact. Only starting it finds that.

Before merging anything, run the first two. Before cutting a release, do the third.

## 4. Merging

Per the doctrine in `HANDOFF-2026-08-14-session2.md` §3: rebase, verify, merge **one at a time**.
Batch-merging five green PRs broke `main` five ways once already — PR CI tests the branch against
*old* main.

```bash
cd "M:/Project AumOS - Open Secure AI Alliance/aumos"
git fetch origin && git log --oneline main..origin/main   # expect empty; a second session writes here
cd M:/wt-depth && git rebase origin/main
cd rust && cargo test -p warrantor-warrant -j 2 && cargo test -p warrantor-warrant --features tls -j 2
cargo clippy -p warrantor-warrant --all-targets -j 2 -- -D warnings
cd .. && node --test rust/warrant/src/console/console.test.js
cd desktop && node --test test/*.test.js
```

`gh pr merge` is blocked on this repository; use
`gh api --method PUT repos/MuVeraAI-Corporation/Warrantor/pulls/<N>/merge -f merge_method=squash`.

Two environment notes that cost time this session: **never pipe cargo through `head`** (SIGPIPE
orphans rustc and corrupts `target/`; write to a log and grep after), and **use `-j 2`** — `clippy`
and the NSIS icon step both died with Windows resource-exhaustion errors at higher parallelism.
